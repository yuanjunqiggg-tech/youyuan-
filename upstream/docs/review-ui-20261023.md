# UI 审查（2026-10-23）

审查范围：命令链中心、知识库与上下文、以机器人身份说话、互通端信息（4 tab）、控制台新增的四处（能力参数编辑 / 掉线横幅 / 二维码过期 / 官方适配器「不支持」）、托管账号卡片的头像 / 令牌 / 换皮肤。

方法：`python -m http.server 8777` + `playwright-cli`，视口 **375×812** 与 **320×640**，深色（`data-theme=dark`）与浅色各测一轮；DOM 尺寸、`scrollWidth`、`getBoundingClientRect`、`getComputedStyle`、对比度全部实读，不靠目测。
复现用的最小页面在 `docs/ui-harness/`（`qq.html` / `chains.html` / `accounts.html` / `audit.js`），只加载真实 CSS 与真实 JS 模块并打桩接口，**未改动任何项目源码**。

---

## 结论

**不通过。** 布局适配这一关是过了的（375 / 320 全无横向溢出，破图 0，重复 id 0），但**可读性和可点性不过关**：最该被看见的三处——命令链主按钮、掉线横幅、危险提示——在深色主题下对比度只有 1.72 / 3.82 / 3.54，其中主按钮白字几乎糊在背景里。

三句话：
1. 命令链中心的主按钮白字打在浅青底色上（1.72:1），深色主题下等于看不见字。
2. 三个新折叠面板的标题栏永远写着「读取中…」，用户不点开就以为卡死了。
3. 全站 10px 字号占了绝对多数（单屏 87 处），叠出 7～9 级字号，这才是「UI 太乱」的直接来源。

## 阻断问题（必须修）

### B1 · 命令链主按钮白字对比度 1.72:1，深色主题下看不清

- 位置：`css/youyuan_chain_center.css:21`（`.yycc-act.is-primary{background:var(--phx-primary);color:#fff}`）
- 实测：深色主题 `--phx-primary` = `#68d8c5`，`#fff` 文字对比度 **1.72:1**（AA 要求 4.5:1）。受影响元素：「新建命令链」「启动」，375 宽下分别是 166×34、148×32。
- 复现：`chains.html` → 深色 → 看顶部第一个按钮和任意一行的「启动」。
- 原因：颜色写死 `#fff`。同一套主题里 `--phx-on-primary` 深色是 `#0d2422`，控制台其它按钮用的就是 `var(--phx-on-primary, #fff)`。
- 期望：改成 `color:var(--phx-on-primary,#fff)`，深色下实测应 ≥ 7:1。

### B2 · 掉线横幅的「重连」按钮 42×25、关闭 36×22，且掉线原因被截断

- 位置：`css/youyuan_qq_console.css:1150-1168`（`.yyq-drop-act{padding:4px 10px}`、`.yyq-drop-x{width:22px;height:22px}`）、`:1146-1149`（原因 `white-space:nowrap` + 省略号）
- 实测（375）：横幅整体 317×49，重连按钮 **42×25**，关闭 **36×22**；原因行可视 180px / 全文 266px，被截成「4 分钟前断开 · OneBot WebSocket 连接被…」，**错误码 1006 正好被切掉**；横幅文字 `#d25050` 对深色底 3.82:1，白字按钮 4.20:1。
- 复现：`qq.html` → 顶部状态带（已注入一次掉线）。
- 期望：两个按钮 ≥44×44（重连至少 44 高、关闭 44 宽），原因允许折行两行（`white-space:normal`），横幅文字对比度 ≥4.5:1。
- 附注：掉线横幅出现后状态带从 52px 涨到 **109px**（占 812 屏的 13%），且挤在同一块里，可考虑独立成条。

### B3 · 三个新折叠面板的标题永远显示「读取中…」

- 位置：`js/youyuan_qq_knowledge.js:96-99`、`js/youyuan_qq_serverinfo.js:121-123`（`if (loading) return "读取中…"`），而 `load()` 只在 `ontoggle` 展开时才触发（`knowledge.js:245-248`、`serverinfo.js:332-340`）
- 实测：页面加载后不展开，「知识库与上下文」「互通端信息」两条摘要文本恒为 `读取中…`；展开并加载完成后才变成「文档 12 · 片段 348 · 上下文 31%」「在线 7 · 玩家 42」。对照「以机器人身份说话」因为摘要同步计算，一开始就显示「1 个群可选」。
- 复现：`qq.html` 打开即看三个折叠条的右侧小字。
- 期望：未展开时摘要不要承诺一个不会发生的加载。要么初始 `loading:0` 显示「点开查看」，要么挂载时就静默拉一次（三个接口都是只读 GET，代价很低）。

### B4 · 知识库断网时把「读不到」渲染成「你的库是空的」

- 位置：`js/youyuan_qq_knowledge.js:119-175`（`ragPanel()` 完全不读 `yyK.err`）
- 实测：`A()` 返回 `{ok:false,error:"网络不可用"}` 时，面板显示「文档 0 篇 / 片段 0 段 / 已建向量 0 段 / 向量维度 未配置嵌入模型 / 占用空间 0 B / 检索模式 仅关键词」，下面接「知识库还是空的。加上资料后，机器人在群里回答时会先检索这里。」——错误信息只出现在折叠标题里，正文一个字都没提。
- 复现：`qq.html` 控制台执行 `window.__OFFLINE__=true`，再展开「知识库与上下文」。
- 期望：请求失败时正文顶部给一条明确错误条（复用 `.yyk-warn`），并把 0 值换成「—」，不要输出「知识库还是空的」。

### B5 · 命令链首次加载失败会永久卡在「正在读取命令链目录…」

- 位置：`js/youyuan_chain_center.js:198`（写骨架）、`:203-206`（失败直接 `return`，不清骨架、不给重试）
- 实测：首屏 `rows` 为空 → 渲染骨架 → 请求失败 → 只剩骨架 + 顶部一行「网络不可用」，列表区没有重试入口，刷新按钮在概览卡右上角，离得很远。
- 复现：`chains.html` 控制台执行 `window.yyChainRows=[]`、清空 `#yy-chain-list` 后置 `window.__OFFLINE__=true` 并调 `yyChainsRefresh()`。
- 期望：失败时把骨架替换成空状态卡（复用 `.yycc-empty`），写「读不到命令链目录：<原因>」并带一个「重试」按钮。

### B6 · 知识库文档的删除按钮只有 36×22

- 位置：`css/youyuan_qq_console.css:1090-1098`（`.yyk-del{width:22px;height:22px}`）
- 实测：375 宽下每个 × 按钮 36×22（含内边距），紧贴文档标题；这是**不可恢复的删除**（`knowledge.js:362-374` 有 `confirm`，但按钮本身太小，容易误触到相邻行）。
- 复现：`qq.html` → 展开知识库 → 文档列表右侧。
- 期望：点击热区 ≥44×44（视觉可以仍是 22px 图标，用透明 padding 撑开），并与标题保持 ≥8px 间距。
