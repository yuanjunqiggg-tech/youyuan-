# 执行设备文件上传与续传

建筑导入前的文件传输与游戏内建筑作业是两个独立阶段。文件上传完成不代表导入完成；此接口不会放置方块、传送机器人或自动执行插件。

受现有账号/设备认证保护的接口：`/api/youyuan/files/transfer`。MCP 使用通用 API 调用器，Lua、Python、C++ 使用已有 host HTTP/API 调用方式；选择子账号时沿用账号 API 前缀，不要绕开账号权限。

| 操作 | 请求 | 真实返回与含义 |
|---|---|---|
| 建立 | POST JSON `{id,name,size}`；id 为随机32位小写十六进制 | `upload.id/offset/chunks/complete`；同id、同文件名与大小的请求幂等 |
| 查询 | GET `?id=...` | 已持久化确认的 offset 与每块 SHA-256；不得把已发送字节当已接收 |
| 传块 | PUT `?id=...&offset=...&sha256=...`，body为原始字节 | 固定1MiB，最后一块除外；服务端逐块验SHA，落盘同步后推进offset |
| 完成 | POST `?id=...`，可加`sha256=完整文件哈希` | 校验全部已存块及总字节数，计算完整SHA，原子提交后返回path；不会覆盖原文件 |
| 取消记录 | DELETE `?id=...` | 删除未完成暂存与记录；已完成的用户文件保留 |

上传单文件最多2GiB，同时最多8个未完成记录、4GiB暂存预留；记录保留24小时。完成文件留在当前执行设备“用户上传”目录。客户端仅保留随机票据与文件关联，重新选择同一文件可续传；先校验本地文件与已确认前缀，再继续上传。重新上传的文件使用独立完整票据文件名，不覆盖同名用户文件。

连接中断后先GET查询偏移，再决定是否重新发送同一块。重复同一块会核对位置、大小与SHA；不同内容不允许覆盖。完成请求丢响应也先查票据，不能因此再次启动建筑导入。此处的幂等重试只适用于文件字节，不适用于游戏指令、NBT放置、导入任务或其他可能已执行的写操作。

浏览器入口使用 `yyUploadFile(file,{onProgress,signal})`；host文件页显示实际已确认字节与进度。已完成票据每次使用前会核实最终文件存在、大小和SHA；被删除或更改的文件不会返回可用路径。
