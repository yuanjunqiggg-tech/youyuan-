# 九、实战案例：粒子作图 —— 分叉取样与大数圆规

来源：网络流传的 MC 基岩版"纯指令画粒子图案"作品（原作者与作品名从略）。
本页只保留可迁移的技法，不涉及具体作品设定。

这类作品的共同点：**不靠手填成百上千个坐标**，而是把 `execute` 的朝向运算当作一支"画笔"，
让一条命令一次算出图案上的一批采样点，末尾用 `particle` 在每个落点画一下。

读懂这一个案例，就能迁移到大多数"指令画圆 / 画眼 / 画花 / 画魔法阵"的写法。

> ⚠️ 本页把 **能从命令本身确认的机制** 与 **依赖现场摆放的推断** 分开写。
> 标着"（推断）"的部分必须拿实际的两个 `a`、`c` 盔甲架间距与朝向来核对，
> **不能当成通用公式照抄**。
> 涉及 `execute` 子命令语义 / 分叉公式 / 局部坐标方向的权威依据，见 `10-官方文档摘录-execute与坐标.md`。

## 1. 它最终画出什么

一个正对玩家的粒子图案：

- **外层**：上下两条弧在中轴左右两端**收尖**，构成"眼形 / 纺锤形"轮廓；
- **内层**：正中**嵌一个圆**（一圈采样点，中心另有 `end_chest` 点缀）。

图案不沿玩家轨迹拖尾：每刻按玩家**当前**位置重算并重新落点，所以站着不动时是稳态图案。

## 2. 触发结构：记分板 + 两档阈值

```mcfunction
/scoreboard objectives add pwr dummy
```

| 档位 | 命令 | 作用 |
|---|---|---|
| 累积 | `scoreboard players add @a[hasitem={item=ender_eye,location=slot.weapon.mainhand}] pwr 1` | 手持末影之眼时**每 20 刻**（约 1 秒）+1 |
| 4 分 | 两条粒子长命令 | 常驻图案：内圆 + 外轮廓 |
| 5 分 | 伤害 / 音效 / 震动 / 水晶 + `reset` | 爆发一次，随即清零重新累积 |

要点：

- `hasitem={...location=slot.weapon.mainhand}` 是**手持检测**，不是背包检测。
- 累加命令挂"循环·保持开启·20 延迟"的命令方块；粒子命令挂"循环·保持开启·无延迟"（每刻）。
- `reset` 写在爆发之后 → **"蓄力 → 爆发 → 归零"是一个循环**，不是一次性技能。
- 到 5 分那一帧，4 分命令与 5 分命令**同时命中**；`reset` 让 4 分图案在该帧后停止。

## 3. 辅助实体：a–c–a 三座盔甲架

摆放：**两座名为 `a` 的盔甲架面对面，中间放一座名为 `c` 的盔甲架**。

它们**不是攻击目标、不是特效载体**，只提供两样东西：

- **位置**：`c` 是图案的基准原点；
- **朝向**：两个 `a` 提供两个不同方向，供 `rotated as` / `facing entity` 反复取用。

## 4. 机制一：分叉取样 —— 一条命令打出很多点

把重复段压缩后，画图命令的骨架是：

```mcfunction
execute if entity @a[scores={pwr=4..}] as @e[name=c] at @s \
  rotated as @e[name=a] positioned ^1 ^ ^ facing entity @e[name=a] feet \
  positioned as @s positioned ^ ^ ^1  facing entity @e[name=a] feet \
  positioned as @s positioned ^ ^ ^1  facing entity @e[name=a] feet \
  positioned as @s positioned ^ ^ ^1  facing entity @e[name=a] feet \
  as @a[scores={pwr=4..}] ...（后续把落点折返到玩家面前）... \
  run particle minecraft:redstone_torch_dust_particle
```

关键在于 `as` / `at` / `rotated as` / `facing entity` 的**分叉（forking）**：
每命中 N 个实体就复制 N 条执行实例，链式嵌套则按 **n^x 幂次**增长，全部在**同一 tick** 内执行完。
（权威依据见 `10-官方文档摘录-execute与坐标.md` 第 2 节。）

这里每次方向选择都能在左右两个 `a` 之间二选一，所以一条命令能一次性得到很多条不同朝向的计算链，
末尾各落一个粒子 —— 这就是"一整圈点"的来源。

**数一数**：该命令中多目标选择器 `@e[name=a]` 出现 **5 次**（1 次 `rotated as` + 4 次 `facing entity`）。
若两座 `a` 都被命中，则 4 分档产生 **2⁵ = 32** 条实例；末尾 `as @a[scores={pwr=4..}]` 再按
"分数达标玩家数"相乘。**5 分档**多了 `32/16/8/4/2/1/0.5` 的逐级段，倍数更高。

> 注意：这只是**机制上限**，不是"必然产生 32 个不同点"。多座 `a` 若被误匹配、或路径重合，
> 实际点数会变。要精确报数，必须知道 `@e[name=a]` 的实时匹配数。

## 5. 机制二：大数圆规 —— 为什么有 100000 和 282842.71

取得各种朝向后，命令切到玩家身上，出现一串吓人的数字：

```mcfunction
... as @a[scores={pwr=4..}] positioned as @s positioned ^ ^ ^1.5 \
  positioned ~ ~-100000 ~ rotated as @s positioned ^-100000 ^ ^ \
  facing entity @s feet positioned ^ ^ ^282842.712 rotated as @s \
  positioned ^ ^ ^100000 positioned ~ ~-100000 ~ facing entity @s feet \
  positioned ^ ^ ^282842.712 rotated as @s positioned ^100000 ^1.52 ^100004 \
  run particle ...
```

**`100000` 不是要把图案画到十万格外**（推断）。它是把计算位置暂时甩远，
再用"朝向玩家""按朝向走一段""切回玩家朝向"等操作，把远处算出来的位移**折返回玩家身边**。

`282842.71 ≈ 2 × √2 × 100000`，是配合十万格横 / 纵位移使用的对角线长度。
按此理解：**它在借游戏自带的朝向与局部坐标运算做坐标变换**，
而不是先自己算出圆的三角函数坐标再逐点填写。这就是"大数圆规"名字的由来 ——
用极大的数当"半径"，靠 `rotated` / `facing` 把它转成图案上的点。

> **推断标注**：官方文档只记载了 `^left ^up ^forward` 的局部坐标语义与"朝向影响局部坐标"，
> **没有**任何"用大数折叠坐标"的记载（见 `10-官方文档摘录`）。上面这段是**由命令结构反推的推断**，
> 不是文档结论；精确落点必须实测。

末尾 `^100000 ^1.52 ^100004` 里，十万格用于抵消前面的远距离变换，
真正留下的是 **`1.52` 与 `4`**，把图案安在玩家面前、接近视线高度（推断）。

## 6. 两种粒子各画什么（含推断）

| 粒子 | 出现位置 | 判断 |
|---|---|---|
| `redstone_torch_dust_particle` | 第一条长命令 | 内侧圆的采样点（推断） |
| `end_chest` | `at @a positioned ^ ^1.52 ^4` | 玩家前方 4 格处的**中心点缀**，不负责画整圈 |
| `colored_flame_particle` | 第二条长命令 | **外层尖头眼形轮廓**（推断） |
| `end_chest`（5 分档） | `positioned ^ ^1.52 ^4` | 爆发前的定位标记 |

边界说明：我们**没有**两个 `a` 与 `c` 的精确坐标、朝向，也没有目标网易服版本的实测落点。
所以"哪条画内圆、哪条画外轮廓"是按成品形状与命令结构给出的推断，
**不能从这两行文字严谨证明每个采样点的精确曲线方程**，也不宜直接称它为标准椭圆。

## 7. 5 分档：爆发

```mcfunction
execute as @a[scores={pwr=5..}] at @s run playsound ambient.weather.lightning.impact @a
camerashake add @a[scores={pwr=5..}] 0.5 1
execute as @a[scores={pwr=5..}] at @s positioned ^ ^ ^32.5 \
  at @e[tag=!保护,r=32,type=!item,type=!armor_stand] rotated as @s \
  positioned ^ ^ ^100001.2 facing entity @s feet positioned ^ ^ ^100000 \
  run damage @e[r=3,c=1,type=!item,type=!armor_stand] 100 block_explosion
```

同样复用"大数圆规"把落点推出去取最近实体：`damage ... 100 block_explosion` 打**最近的一个**非物品非盔甲架实体。

- `block_explosion` 是**伤害类型**，不会真的破坏方块；
- `camerashake add @a ...` 是对**所有玩家**震屏，不只是施法者 —— 做单人技能时要收窄选择器；
- 之后 `summon ender_crystal ~ ~ ~` 造出水晶，紧接 `damage @e[type=ender_crystal] 0`，
  这是"召唤后立刻清掉 / 触发"的常见套路。

## 8. 精确复现还需要什么

要 1:1 还原图案尺寸与朝向，必须先拿到：

1. 两座 `a` 与 `c` 的**精确坐标**（决定图案半径与"收尖"程度）；
2. 两座 `a` 的**朝向**（决定两个可选方向，是图案形状的关键）；
3. 目标服的**版本**（旧 / 新 execute 混用、粒子名支持情况）。

缺这些条件时，只能照抄机制、重调参数，不能保证落点一致。

## 9. 踩坑与性能

| 风险 | 说明 |
|---|---|
| 每刻几十条路径 | 长命令挂在**无延迟循环**上，玩家一多粒子量线性上涨，务必控制 `@a` 范围 |
| 分叉依赖 `a` 的朝向 | `a` 被推动 / 换位后图案立刻变形；要给盔甲架 `{NoAI:1}` 或 `invisible` 之类保护 |
| 分叉无上限 | `@e[name=a]` 若因故匹配到多座，路径数翻倍，粒子爆炸 |
| 5 分与 4 分同帧 | 忘记 `reset` 会一直停在爆发态反复触发 |
| 震屏/音效是全体的 | `@a` 默认全员，做个人技能要改成 `@s` 或带 tag |
| 伤害误伤 | `damage @e[r=3,c=1]` 取最近目标，可能打到友方；需要加 `tag=!保护` 一类排除 |

## 10. 一句话总结

**`a–c–a` 负责一次生成多个取样方向；长串 `positioned / facing / rotated` 负责把方向变换成玩家面前的
作图点；两种粒子分别叠出内圆与尖头外轮廓；记分板 4 / 5 分决定"显示图案"还是"爆发并归零"。**
