# QQ 群 AI：身份、上下文与可选检索记忆

2026-10-18。本说明对应现有官方 QQ 与 OneBot 两条适配路径，不增加第三方机器人登录流程。只处理机器人实际收到的群事件，不拉取 QQ 完整历史。

## 身份与引用

- 原始事件保存 adapter、bot_id、group_id、sender_id、message id、reply_to_message_id、昵称与时间。OneBot 使用 `json.Number` 解析长数字 ID，不经 float64 舍入；缺失/不可靠 ID 不推算成 QQ 号。
- 模型收到的 sender_id 是依据适配器、机器人实例、群和真实用户 ID 生成的稳定别名。昵称独立显示，允许重名、改名；官方 openid 不直接塞入模型文本。
- 当前提问与背景都是结构化 JSON，保留消息和引用 ID。准确引用目标优先于词法/向量相似度；缺少引用原文时不得猜测说话人。
- 自己发出的 OneBot 消息、官方事件明确标为 bot 的作者不会被递归送入群 AI。系统规则明确机器人身份；自定义提示不能要求冒充服主或真人。
- AI 历史与陪聊会话按 adapter、bot、group 分桶，个人 AI 历史再分 user、管理员权限、所选模型。AI 回执保留来源群，不依赖跨群可能重复的消息 ID 猜目标。

## 上下文与保留边界

近期背景最多 64 个桶，每桶最多 80 条、正文合计最多 32,000 字符；单条正文至多约 2,000 字符。AI 历史最多 128 个个人会话、8 个轮次，并按字符预算淘汰完整问答对。默认 TTL 为 24 小时，可设置 1–720 小时。

`context_chars` 默认 6,000、上限 16,000，用于分配近期背景、旧 AI 历史和检索背景的预算；当前提问也有独立截断上限。压缩采用保留身份与引用字段的有界摘录，明确标为 `bounded_extractive_excerpts_not_factual_summary`，不会把截断文本冒充模型总结、事实或授权。未知消息不会被编造。

读取/新消息时清理过期条目，宿主 QQ 模块启动后每 10 分钟还会清理闲置桶、AI 历史和持久索引。维护函数已有本地回归，尚未做生产长跑或资源曲线验收。

## 可选 RAG 配置

长期检索默认关闭。通过现有设备认证的 QQ 配置接口设置，示例不含凭据：

```json
{
  "assistant": {
    "memory": {
      "enabled": true,
      "embedding_model": "你在现有AI模型管理中配置的嵌入模型名称",
      "ttl_hours": 24,
      "context_chars": 6000
    }
  }
}
```

`embedding_model` 引用现有 `aiStore` 的 OpenAI 兼容配置，不在 QQ 配置或向量索引复制密钥。需要真实的 base_url、model_id；远端服务还须已有 API key。本机 loopback 服务允许无 key。请求 `/v1/embeddings`（兼容 base_url 已带 `/v1` 或 `/embeddings`），只接受响应返回的非零、有限数值向量，维数范围 1–2048；不使用随机向量或字符哈希冒充 embedding。

索引按群进行余弦检索，同时保留消息身份与引用来源。模型没配置、缺远端密钥、服务失败、返回非法向量、两个 embedding 槽位均忙或条目尚未索引时，明确返回 `lexical_fallback_*` 状态并使用词法检索。向量入库异步执行，最多两个并发请求；不无限排队、不无限重试。单次请求超时 8 秒。

本地文件为宿主 dataDir 下 `qq-group-memory.json`，只有显式开启后才存收到的事件。最多 32 个群/机器人桶，每桶 160 条，每条检索正文约 700 字符；索引文件最大 24 MiB。超过文件限制或写入失败会通过 `persistence_error` 明确报告，不能把仅在内存中的条目说成已落盘。代码使用 0600 写文件，实际 Windows ACL 仍由宿主目录决定。

更换 embedding 模型时，以模型端点与 model_id 指纹区分已存向量；不把旧模型的向量当成新模型索引。未匹配或未索引的条目继续词法回退。

## 查看、删除和清空

沿用设备 API 认证边界，只能选择当前配置中启用的群：

- `GET /api/qq/memory?group=<群ID>`：查看是否开启、有效条目/已索引条目数、embedding 是否配置、检索状态、TTL、预算和持久化错误；不返回模型密钥或服务错误原文。
- `DELETE /api/qq/memory?group=<群ID>&message_id=<消息ID>`：删指定消息，同时使该群既有 AI 历史和等待任务失效，避免旧回答重新带回已删内容。
- `DELETE /api/qq/memory?group=<群ID>`：清空该群近期消息、AI 历史和持久索引；其他群保留。

删除/清空采用代际校验：模型或 embedding 请求在删除前已经发出时，之后返回的答案/向量不能恢复已删内容。网络已经发出的数据无法撤回；本功能不声称删除第三方服务已接收的数据。

## 已验证与缺口

本地测试覆盖同名不同 ID、长数字 ID、官方/OneBot 引用解析、群/机器人分桶、正文与上下文预算、TTL 和闲置维护、空库/关闭/缺密钥回退、真实回环 embedding HTTP 请求响应、非法/零向量拒绝、持久化重载、删除期间迟到向量不复活，以及清空期间模型回答被丢弃。

这些是本地夹具与代码运行证据。未选择真实外部模型凭据、未调用生产 embedding 服务、未发送 QQ 消息或图片，也未验收真实群事件权限、官方/OneBot 真群链路、真实模型归因质量或长跑性能。接入配置和后台 API 已具备，设置页面入口不在本轮范围。
