# 五、坐标存储、地皮与数据分配

基岩版没有文件/数据库，**所有持久数据都存在记分板里**（每个玩家一套 objective，或一个"全局"记分项）。

## 1. 玩家坐标锚点（存/读/删）

用 6 套 objective 存 6 个槽位的 x/y/z：

```mcfunction
scoreboard objectives add 坐标1x dummy
scoreboard objectives add 坐标1y dummy
scoreboard objectives add 坐标1z dummy
# …槽位 2..6 同构

# 存：把玩家当前坐标写进对应槽位（x/y/z 是玩家自带的"坐标分数"）
scoreboard players operation @s 坐标1x = @s x
scoreboard players operation @s 坐标1y = @s y
scoreboard players operation @s 坐标1z = @s z

# 读：把分数还原成 tp 参数（注意必须用"整数"目标坐标）
execute as @s at @s run tp @s <x> <y> <z>
```

要点：
- 玩家内置分数 `x` / `y` / `z`（以及 `rx` / `ry`）可直接 `operation` 赋值。
- 分数是整数；存小数坐标会丢精度（要亚方块精度得额外存小数部分）。
- 维度要**另存一个分数**记录（主世界/下界/末地），传送时先 `in <维度>` 再 tp。

## 2. 全局 ID 分配（新玩家发号）

```mcfunction
# 全局计数：一个叫 ID 的假玩家持有下一个可用编号
scoreboard objectives add ID dummy
execute as @a[tag=!数据] run scoreboard players add ID ID 1
execute as @a[tag=!数据] run scoreboard players operation @s ID = ID ID
tag @a[tag=!数据] add 数据
```

要点：**假玩家**（不存在的名字）可以持有分数，当作全局变量用（`ID ID` 即"假玩家 ID 的 ID 分数"）。新玩家发号后必须打 tag，否则每刻重发。

## 3. 二进制位存储（用容器塞整数）

把一个大整数按二进制拆到箱子/容器的多个槽位（每个槽位表示一位），可存远超记分板范围的值：

```mcfunction
# 从 ID 中逐位取出，写进容器槽 0..13
execute as @e[c=1,type=armor_stand,name=存储,scores={ID=8192..}] at @s run replaceitem block ~ 318 ~ slot.container 13 air 1 0
scoreboard players remove @e[type=armor_stand,name=存储,scores={ID=8192..}] ID 8192
execute as @e[c=1,type=armor_stand,name=存储,scores={ID=4096..}] at @s run replaceitem block ~ 318 ~ slot.container 12 air 1 0
scoreboard players remove @e[type=armor_stand,name=存储,scores={ID=4096..}] ID 4096
# …2 的幂从大到小逐位扣减
kill @e[type=armor_stand,name=存储,scores={ID=..0}]
```

要点：**从大到小**逐位 `remove`，能减掉就说明该位为 1。容器放在固定坐标 `~ 318 ~`（Y=318 是常用高位，避免与建筑冲突）。

## 4. 地皮 / 空岛分配（螺旋寻址）

给新玩家分配一块地皮：用一个"已分配数量"计数器推导坐标，走**螺旋（方形环）**递增。

```mcfunction
# LandX / LandZ 是中心偏移，AddX / AddZ 是本步增量，"计数"决定走的方向
execute if score 计数 分配 matches 1.. run <分配一步>
execute if score LandX 计数 matches 0.. if score LandZ 计数 matches 0.. if score LandX 计数 = LandZ 计数 run scoreboard players set AddX 计数 -1
scoreboard players set AddZ 计数 0

scoreboard players operation XZCount 计数 = LandX 计数
scoreboard players operation XZCount 计数 += LandZ 计数
# 其余边界条件同理，逐步改 AddX/AddZ
scoreboard players operation LandX 计数 += AddX 计数
scoreboard players operation LandZ 计数 += AddZ 计数
```

要点：这类算法**逐条用 `if score` 判断边界**，不写循环——每条 execute 就是一个"状态转移规则"。

## 5. 计数 / 榜单

```mcfunction
# 计在线人数
scoreboard players set 人数 方块 0
execute as @a[x=204,y=67,z=249,dy=7,dz=8,dx=18] run scoreboard players add 人数 方块 1

# 倒计时
execute if score 人数 方块 matches 2.. run scoreboard players remove 倒计时 方块 1
execute if score 人数 方块 matches ..1 run scoreboard players set 倒计时 方块 60
```

`dy/dz/dx` 是**区域选择器**：以 `x,y,z` 为角点的长方体（相对玩家的 `dx=0,dy=0,dz=0` 就是"正好一个方块位置"，用来做精确位置判定）。

## 6. 精确位置判定技巧

```mcfunction
# 判断玩家是否在方块 (x,y,z)：用 dx=dy=dz=0 的零体积选择器
execute as @a at @s if entity @s[x=~,y=~1.4,z=~,dx=0,dy=0,dz=0] unless entity @s[x=~,y=~1.7,z=~,dx=0,dy=0,dz=0] run tellraw @a {"rawtext":[{"text":"下蹲"}]}
```

原理：站着时眼高 ≈1.7，下蹲 ≈1.4；用两个零体积框分别框住 y=~1.4 和 y=~1.7，命中前者不命中后者 → 判定为下蹲。

## 7. 常见坑

| 症状 | 原因 |
|---|---|
| 数据重启丢失 | 存在假玩家/临时实体上的数据会随清理消失，重要数据要落记分板 |
| 坐标精度丢失 | 记分板只存整数 |
| 维度串了 | 忘了单独存维度分数 |
| 分配错乱 | `add` 没有先清零，或新玩家没打 tag 被重复分配 |
| 假玩家冲突 | 用普通玩家名当假玩家名会被真人同名覆盖 |
