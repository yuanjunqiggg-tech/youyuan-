## 事故一：「点击连接服务器一点反应没有」（用户主诉）

排查过程（CDP 连真实 Chrome，线上 toolbox `?device=linux-server` 页面实测）：

1. 页面加载无 JS 报错；`doConn` 存在、按钮 onclick 正常、token 已填。
2. **第一次点击（输入框为空）**：`youyuan_room_discovery.js:37` 守卫 → toast「请输入服务器号、房间号或分享链接」→ return。toast 一闪而过 = 用户看到"没反应"。
3. **第二次点击（手动填 98014267）**：走 discover → POST `/api/youyuan/rooms` → Go 宿主转发到认证服务 `/api/game/discover` → **线上返回"暂未开放的认证操作"**。
4. 定位：该文案出自 `auth-service/engine.go:332`（kernel action switch 的 default）→ **线上 kernel.wasm 是旧版，没有 room_discover action**（engine.go 源码有，`grep -c room_discover kernel.wasm` = 0 实锤）。
5. 修复：`auth-service/build.ps1` 重编 wasm（编译后 grep = 2）→ `npx wrangler deploy` → Version 719b04cd → 线上复测 discover 正常返回（ok:true）。
6. 残留：rental/lobby 两类返回"该类别官方查询失败，请检查账号状态后重试"，local 正常 → **账号会话问题**，非代码。令牌 validate 通过（valid:true, scope game:connect）。
7. 前端补强（已提交未发布）：空输入时自动拉 `/api/bot/status` 预填当前连接的服务器号。

**为什么 21:39 之前没炸**：kernel.wasm 是 10-19 10:36 编译的旧版，room_discover 是之后才进 engine.go 的——线上一直是"部署落后于源码"。

## 事故二：今晚服务器失联 + 机器人集体掉线（WorkBuddy 责任，如实记录）

时间线：
- 22:20 左右启动 `deploy_linux_bin.py` 从本机 SFTP 直传 51MB 新二进制（B3）。
- 上传爬了 20+ 分钟（≈43KB/s），**把服务器 inbound 带宽占死** → 游戏机器人连接（吃上下行）全掉 → 用户看到"机器人全部下线、服务器连不了远端"。
- 22:40 中止（kill）部署任务。服务器 outbound 恢复，但 **sshd 仍不回 banner**（TCP 能 accept）。
- 判读：服务器处于内存耗尽/交换颠簸或 CPU 卡死状态；也可能叠加云防护层对新连接的限流。
- 22:50 挂 `server_recovery_daemon.py` 每 90s 探测，SSH 恢复即自动诊断+拆弹+恢复服务。

**教训（Codex 必须遵守）**：
1. 向这台服务器传大文件必须限速（建议 ≤200KB/s）或分时段，或干脆走服务器侧拉取（Cloudflare 中转）；
2. 部署脚本输出别接 `| tail`（缓冲导致看不到进度，无法判断走到哪一步）；
3. 修复自动更新脚本/停 timer 之前，**禁止发布任何新版本到 updates 通道**（否则 6h 内 timer 用 APK 砖服务）。
