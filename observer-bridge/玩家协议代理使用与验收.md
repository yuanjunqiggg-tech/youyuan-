# 玩家协议代理：0.10.37 实验版独立组件

这次增加的是可执行的协议代理，不再只有 JSONL 发送器。玩家的连接必须经过代理入口。玩家输入从此入口采集，经独立的认证 HTTP 桥传入工具箱；中心机器人可以留在远处或其他维度。未经过入口的玩家不在覆盖范围内。

## 连接结构

玩家协议客户端 → 玩家代理 UDP 入口 → 真实网易游戏服务器。

两侧各自完成认证、密钥协商、加密和压缩。上游获取同一玩家的新公钥绑定登录链。客户端 UUID/网易 UID 与上游证书身份一致后才转发。没有关闭认证或伪造上游证书。

资源包、世界数据、运行期 PyRPC、未知扩展包、游戏输入按原应用帧顺序转发。只为观测解码必要字段，观测解析失败也保留原始帧。游戏服务器仍决定实际伤害、移动和命令是否成立。

## 使用前提

1. 玩家使用允许配置代理目标地址的协议客户端或启动器适配器。仅打开工具箱网页、仅安装此程序，不会把现有官方客户端自动接入。普通网易手机游戏启动器尚未完成真人界面验收。
2. 为每名接入玩家分别配置自己的游戏 Token、真实 UUID/UID 和采集来源。本实验入口每个进程最多承载一个配置身份，多个玩家用多个独立入口，不能拿一个机器人账号替代全部玩家。
3. 验证网址必须与 Token 的生成服务一致。自己的认证服务签发的 Token 选自己的认证服务；第三方签发的 Token 仍需对应的服务。代理没有冒称全部第三方令牌已迁移到我们自己的认证系统。

## 创建来源与配置

在工具箱已授权的 API/MCP 中调用：

```lua
observerBridge.create({
    name = "玩家输入代理",
    source = "player_input",
    server = "服务器号",
    player_id = "玩家真实UUID"
})
```

`id` 与仅返回一次的 `token` 写入私有配置。复制 `player-gateway.example.json`，填好账号身份、游戏 Token 和采集桥地址。私有配置及序号文件不要发布到插件市场、公开下载地址或日志。外部 HTTP 请求需要 HTTPS；同机部署可使用 `127.0.0.1` 的 HTTP。

Linux：

```sh
chmod 700 youyuan-player-gateway-linux-amd64
./youyuan-player-gateway-linux-amd64 -config ./private/player-gateway.json
```

Windows：

```powershell
.\youyuan-player-gateway-windows-amd64.exe -config .\private\player-gateway.json
```

输出 `listening` 才表示 UDP 入口已启动，`phase=forwarding` 才表示两侧游戏登录已建立。需要远程玩家接入时，将 `listen` 配为服务器可监听的 UDP 地址，并在云服务器安全组开放该 UDP 端口。网页域名或 HTTP 公网隧道不等于 UDP 游戏入口；当前示例默认只监听本机。

`-probe` 使用真实认证的协议测试客户端验收入口。它不代表真人手机客户端已测试成功，也不会自动把服务器上的普通玩家改成接入者。认证端明确返回频繁请求/429 时有限重试，重试只影响登录，不在游戏命令发送路径添加 CPS 限速。

## 三语言与 MCP 读取

Lua、Python、C++ 与 MCP 共用宿主已有的 `observerBridge.events(after, limit)`。读取时保留 cursor，不能反复从零读取再重复执行。

Lua：

```lua
local cursor = 0
local function poll()
    local reply = observerBridge.events(cursor, 256)
    for _, event in ipairs(reply.events) do
        local envelope = event.data
        local fields = envelope.data
        if event.kind == "swing_input" then
            -- Animate 只确认挥臂输入；missed_swing=true 才是明确空挥标志。
            print(event.player_id, envelope.packet_type, fields.missed_swing)
        elseif event.kind == "health_observation" then
            print(event.player_id, fields.current, fields.max)
        end
    end
    cursor = reply.cursor
end
util.schedule(0.05, poll)
```

Python：`reply = host.observerBridge.events(cursor, 256)`，读取 `reply['events']` 和 `reply['cursor']`。

C++：`auto reply = client.invoke("observerBridge.events", yy::json::array({cursor, 256}));`，读取 `events` 与 `cursor`。

外部 MCP 调用同名 API，无需让 AI 从原始包重新猜测字段。这里使用采集桥的事件读取接口；原有 `events.onGlobalSwing` 是服务端模块通道，不能混称它已自动订阅本代理来源。

## 数据定义

| kind | 原始通道 | 含义 |
|---|---|---|
| swing_input | C2S Animate/action=1 | 收到本人挥臂输入，不能单凭它区分打中与空挥 |
| swing_input | C2S PlayerAuthInput/MissedSwing | 明确的空挥输入标志 |
| attack_input | C2S InventoryTransaction/Attack | 本人对指定实体发出了攻击输入，不代表服务器判定命中 |
| position_input | C2S PlayerAuthInput | 本人的位置、俯仰、朝向与客户端 Tick 输入，不当作服务器确认位置 |
| health_observation | S2C UpdateAttributes | 服务器下发给此客户端的本人当前/最大血量；相同血量重复包合并 |

RuntimeID/Tick 用十进制字符串，避免 JSON 丢失 uint64 精度。`server_confirmed=false` 是中心对外部来源的信任标记；血量记录另外保留 `direction=server_to_player` 和 `data.source=server_packet`。不把攻击提交成功当作伤害成功，也不把未知血量默认成 20。

采集桥是可分页的内存历史，宿主重启会清空事件；不是永久日志。它不自动覆盖机器人原有的原生实体缓存。本代理没有实现全服任意实体/任意非接入玩家的血量读取。

## 稳定性与诊断

- `queue_capacity` 可配置 1..1048576，默认4096；采集 HTTP 与游戏转发分离，采集拥堵时计入 `bridge_dropped`。
- `flush_ms` 是网络帧聚合周期，默认10ms；不是命令链频率、每秒命令数量限制，也不是整个采集链的总延迟保证。
- 私有序号先持久化再提交，同一批重试使用同一序号；序号文件有单进程锁。异常退出遗留 lock 时，确认旧进程已不存在后再清理，不能让两个代理共用序号文件。
- 诊断输出包含登录阶段、真实会话错误、双向帧数、观测解码失败、投递/丢弃及最后投递时间，不输出密钥或登录链。
- 本程序独立于主工具箱进程，实验结束关闭入口并撤销对应来源；已有插件、Lua 常驻、Python/C++ 宿主和跨模块通信保持。
