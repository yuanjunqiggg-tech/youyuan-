# 种子地图 v2：结构显示问题审查与改进方案

> 审查对象：`upstream/frontend/js/youyuan_seedmap_v2.js`（2403 行）、`upstream/frontend/css/youyuan_seedmap_v2.css`（833 行）
> 关联：`js/youyuan_seed_page.js`（旧版，1111 行）、`js/features/seed_map.js`（Canvas 第三套，1227 行）
> 方法：**纯源码静态审查**（逐选择器/逐渲染函数），没有读取 `outputs/seed-ui/*.png`（截图留给人工复核），也没有改任何代码。
> 用户原话：**「你的种子查询器结构显示跟一滩狗屎一样」**——本文只回答「为什么像一滩」和「怎么收干净」。

---

## 1. 一句话结论

**问题不在内核，在「一个功能被三套前端同时实现 + v2 自己把地图、图层、列表、图例拆成四个互不对齐的容器」。**
三套前端合计 4741 行 JS + 1377 行 CSS（6118 行）做同一件事；玩家能看到两个名字几乎一样的入口；v2 的地图区里，图标是固定 19px、无聚合、无图例、无精度标识、还会随机被预算裁掉——所以视觉上就是「密密麻麻一滩点，看不出哪是哪」。

---

## 2. 三层原因（从外到内）

### 2.1 产品层：一个功能，三个入口，两套坐标语义

| 入口 | 注册处 | 名称 | 你看到的行为 |
|---|---|---|---|
| 旧脚本（被劫持） | `youyuan_seed_page.js:1090-1105` 注册 `id='seed'`，`youyuan_seedmap_v2.js:2375-2379` 把它的 `open` 改成 v2 | **种子地图** | 打开的是 v2 |
| 更多工具 | `features/others.js:16` | **种子查询器** | 打开的是 Canvas 版（第三套） |
| 首页工具区 | v2 在运行时 push `seedmap2`（`youyuan_seedmap_v2.js:2380-2399`） | 种子地图 | 只在旧入口不存在时才出现 |

原文注释自己承认了：「旧页面（id='seed'，youyuan_seed_page.js）走的是 /api/seed/* 那套近似实现…旧文件不删，万一新页挂了还能手动切回去」（`youyuan_seedmap_v2.js:2365-2369`）。这是**技术上的保险**，但代价是玩家侧多一个入口、维护侧多 3700 行。

坐标语义也不统一：

- v1 `youyuan_seed_page.js:291-294`：`chunkToPx`，屏幕直接按**区块**换算
- v2 `youyuan_seedmap_v2.js:107-108`：`blockOf = chunk*16+8`，显示**方块**，注释强调「屏幕给玩家看的是方块坐标」
- 第三套 `features/seed_map.js` 又有自己的换算

结果：同样一个村庄，三个页面显示的数字不同，用户第一反应就是「这玩意不准」。

### 2.2 布局层：地图不是主角，四个容器在抢空间

当前 DOM（`youyuan_seedmap_v2.js:454-552`）：

```
.sm2  (grid: 1fr 344px)
├── .sm2-main
│   ├── .sm2-bar          种子输入 / 版本 / 维度 / 查看 / 结构图层折叠
│   └── .sm2-mapcard
│       └── .sm2-map      readout + dock + drawer + loading + empty + alert + info
└── .sm2-side             结构概览 + 结构列表 + 要塞 + 说明（4 张卡）
```

问题：

1. **工具条和地图是两张卡**（`.sm2-bar` 26-35、`.sm2-mapcard` 258-265），中间 12px 缝；右栏第一张卡却和工具条顶对齐 → 视觉上地图和侧栏是两列不同的东西。
2. **侧栏 344px 固定**（`css:12`），在 1024–1180 只降到 306px（`css:749-751`）；地图实际可用宽度被压到 60% 左右，而地图才是要看的东西。
3. **地图内又叠 6 层**：读数（12,12）、缩放坞（底部居中）、抽屉按钮（右下）、加载/空态（inset 0）、告警（top 52）、信息面板（左下 282px）。手机上这些层互相打架（见 P0-3）。
4. **侧栏内部再套 2 个滚动区**：`.sm2-side` 自己 `overflow:auto` + `max-height:calc(100vh-96px)`（`css:619-620`），`.sm2-listbox` 又 `max-height:42vh; overflow:auto`（`css:669`）；外层 `.sp-body` 本身就是滚动容器（`css/layout.css:115`）。三层滚动，手指经常滚错层。

### 2.3 符号层：图标、颜色、图例没有形成「可读的编码」

结构信息其实有 4 个维度（类型、维度、精度、距离），但界面上只用了 2 个半：

| 维度 | 现在怎么表达 | 问题 |
|---|---|---|
| 类型 | 19px 圆形徽标 + 颜色 | 颜色有 3 组近似绿/紫；无文字；无图例 |
| 精度 | **完全不表达** | `def.precision` 只在 `iconBudget().exactOnly` 时用来过滤（`js:1623`），玩家看不到「候选/精确」 |
| 距离 | 列表里 `距离 1.2k 方块` | 地图上无感知；列表不按距离分组排序 |
| 维度 | 切换后重载 | 切换成本高；没有「当前维度」常驻标识（只有按钮高亮） |

→ 这就是「一滩」的直接原因：**一堆同质圆点，没有图例、没有层级、没有精度区分、还会互相压住。**

## 4. 目标布局（建议形态）

### 4.1 桌面（≥1280）

```
┌───────────────────────────────────────────────────────────────┐
│ [🔍 种子________×] [版本 1.21.4 ▾] [主世界|下界|末地] [查看]  │  一行，不再折行

├──────────────────────────────────────────┬────────────────────┤
│                                          │ 结构（按距离）  ⌄  │
│              地  图  区                  │ 1. 村庄   1.2k  →  │
│                                          │ 2. 府邸   3.4k  →  │
```

- 地图列 `minmax(0,1fr)`，侧栏 `clamp(300px, 26vw, 360px)`，`gap:12px`
- 只有 **1 个** 侧栏滚动区（列表），概览/图例固定不滚
- 地图内浮层最多 3 个：读数、缩放坞、回原点

### 4.2 平板（768–1279）

- 侧栏折叠成抽屉（已有 `.sm2-drawerbtn`），地图占满宽
- 顶部工具条两行：种子+版本+查看 / 维度+图层

### 4.3 手机（≤640）

- 工具条：种子输入独占一行；第二行「版本 + 维度」；「查看」紧跟种子输入右侧（不单独换行）
- 图层默认折叠（已有逻辑 `js:2341-2346`）
- 抽屉按钮移到**右上角**（`top:8px;right:8px`），不再与信息面板同角
- 信息面板从底部弹出，占满宽，**关闭时抽屉按钮才出现**

## 5. 落地方案（按阶段，不改代码，只给动作）

### 阶段 0：先止血（半天，风险最低）

1. **修 P0-3 同角重叠**
   - 改 `css:804`：`.sm2-drawerbtn{right:8px; bottom:calc(58px + 44px)}`，或直接 `top:8px;bottom:auto`
   - 改 `css:786`：`.sm2-info{bottom:58px}` 保持；确认 info 打开时 drawer 不可点也无所谓（被盖住不再发生）
2. **修 P0-6 死代码**
   - 二选一：后端 `/meta` 补 `unsupported`（推荐，`youyuan_seedv2_routes.go:85-89`），或前端删掉 `readMeta` 里的 `unsupported` 分支，改按 `m.structures` 重建 chips
   - 验收：切 1.15，选「海底废墟」，chip 必须置灰且带 title

   - UI：chips 与图例里给 `ring_approx` 加「候选」角标；详情面板加一句「环位候选，落地后附近 1~2 区块内找」

    - 地图右下角常驻「显示最近 N 个 / 共 M 个」小字，别静默丢

    - 候选：圆 + 虚线圈（CSS `outline:1px dashed`）
    - 要塞：固定「▲」形，不用旋转的圆（同时修 P1/P2 的 `data-strong` 旋转 bug：`css:330-335` 只反转了 `svg`，生产环境是 `<img>`（`js:1655-1663`），图片会跟着徽标一起转 -45°）

## 6. 不建议做的事

| 想法 | 为什么不做 |
|---|---|
| 「把 v2 删了，回到 v1」 | v2 内核（99.7% 群系、13 类结构逐点对拍）是资产；问题在外壳 |
| 「图标再小一点就不挤了」 | 19px 已经接近可点击下限；再小更难点，且不解决重叠 |
| 「全部类型默认都开」 | 默认 8 类已经让地图很密；全开 20+ 类必然一滩 |
| 「用 Canvas 重写图标层」 | 现在的问题是布局与聚合，不是渲染性能；Canvas 会丢掉 `button` 的可访问性与 title |
| 「列表直接显示全部 20000 条」 | 渲染与滚动都会崩；按距离 + 虚拟列表才是解 |
