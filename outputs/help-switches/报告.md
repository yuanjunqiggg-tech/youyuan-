# 群服互通 · 命令注册表 + 帮助菜单（交付报告）

## 已完成

1. **帮助菜单从「拼死字符串」改成注册表投影**：新增 `youyuan_qq_help.go`（`yyQQHelpEntry` / `yyQQHelpRegistry` / `yyQQHelpEntries` / `yyQQHelpText` / `yyQQHelpRegister`）。数据源四合一：`yyQQCapabilities`（能力）、`yyQQSkillDefs`（AI 技能）、`yyGameSkillAll()`（游戏技能）、`yyQQHelpCmdGroups`（固定指令）。菜单不再有第二份定义——`youyuan_qq_assistant.go` 的 `yyQQHelp` 现在只有一行 `return yyQQHelpText(cf, level)`（原 14 行菜单文本已删除）。
2. **按实际权限过滤**：分组标题带角色后缀（· 所有成员 / · 仅管理员 / · 仅超级管理员），`MinRole > level` 的条目整条不渲染。普通成员看不到 `.改头像`、看不到 `/命令`、看不到「🔑 超级管理员」整组。
3. **只显示已启用条目**：能力看 `yyQQCapEnabled`，AI 技能看 `技能开关 && 能力闸门 && 工具开关`，游戏技能看 `Enabled`。被关掉的条目不出现，只在末尾提示「另有 N 项功能在面板里关着」。
4. **触发词分层**：`yyQQTrigger` 新增 `min_role`（0 所有人 / 1 管理员 / 2 超管，缺省 0 兼容老规则）；`yyQQTriggerRun` 在匹配前判定，权限不够整条跳过（不匹配、不占冷却、不吞消息）；`yyQQTriggerLevel` 与 `capability` 动作共用同一套身份判定；POST 夹紧 0..2，GET 回 `roles` 与 `max`。
5. **默认全开**：能力注册表里 `recall` 从 `Default:false` 改为 `true`（其余原本就 true）；技能 `yyQQSkillEnabled` 缺省 true；游戏技能内置项 `Enabled:true`。每一项都有独立开关 key（见 ③ 的 `toggle_key`）。
6. **上限放开**：技能条数 100 → `yySkillMaxCount=200`；触发词条数 60 → `yyQQTriggerMax=120`；两者都不是固定数组，玩家可自建 50+ 条。
7. **新路由登记齐全**：`GET /api/qq/help` 在 `yyQQCapRoutes` 里注册（因此 `youyuan_qq.go` 一行未改），并同时登记 `youyuan_catalog.go` 的 `yyAPIRoutes`（`api_qq_help`）与 `youyuan_mcp_links.go` 的 `yyMCPReadPaths`（只读）。

## ② 帮助菜单新结构（`yyQQHelpEntry`，`youyuan_qq_help.go:27`）

| 字段 | 类型 | 含义 |
|---|---|---|
| `group` | string | 分组 key：chat / query / ai / cap / game / skill / admin / root |
| `group_title` | string | 渲染用标题，含角色后缀，如「🤖 机器人能力 · 仅管理员」 |
| `icon` | string | emoji |
| `command` | string | 生效命令串（`command_aliases` 优先，能力首词也走别名） |
| `desc` | string | 一句话说明 |
| `min_role` / `min_role_text` | int / string | 0 成员 / 1 管理员 / 2 超管 |
| `toggle_key` | string | 开关 key：能力=`kind`、AI 技能=`id`、游戏技能=`gs:<name>`；空=写死不可关 |
| `source` | string | command / capability / skill / game_skill |
| `enabled` | bool | 当前开关状态（不受权限影响） |

渲染顺序：分组固定顺序 → 组内按 `min_role` 升序。正文结构不变（`✦ 游园 · 群服助手` / `你的权限：X` / 分组 / 末尾 `@机器人` 提示）。

## ③ 前端需要改的接口契约

**新增只读接口** `GET /api/qq/help?level=0|1|2&raw=1`（默认 `level=2`）
```json
{"ok":true,"level":2,"level_text":"超级管理员",
 "entries":[{"group":"cap","group_title":"🤖 机器人能力 · 仅超级管理员","icon":"🧑",
             "command":".改头像 图片URL","desc":"更换机器人 QQ 头像","min_role":2,
             "min_role_text":"超级管理员","toggle_key":"avatar","source":"capability","enabled":true}],
 "text":"✦ 游园 · 群服助手\n…","groups":[{"key":"cap","title":"🤖 机器人能力","order":3}],
 "roles":["成员","管理员","超级管理员"],"hidden_disabled":3}
```
- `raw=1` 返回未过滤全集（含未启用、更高权限、`source:"skill"`），用于面板「帮助预览」；
- 不带 `raw` 时与群内实际菜单内容一致（可做「成员视角预览」开关）。

**开关落到既有接口，不新增写接口**：
- 能力 → `POST /api/qq/caps {"caps":{"<kind>":false},"limits":{...}}`（`toggle_key` 即 kind）
- AI 技能 → `POST /api/qq/assistant {"assistant":{"skills":{"<id>":{"enabled":false,"word":"…"}}}}`
- 游戏技能 → `POST /api/qq/skills {"skills":[{"name":"…","enabled":false}]}`（`toggle_key` 去掉 `gs:` 前缀）

**行为变更需同步**：`/api/qq/triggers` GET 新增 `roles`、`max`（120），每条规则多 `min_role`；POST 接受 `min_role`（越界夹紧到 0..2）。前端规则编辑器请加「适用身份」三选一，并在列表显示角色徽标。`/api/qq/caps` 里 `recall` 的 `default` 现在是 `true`，「恢复默认」要显示为开启。
