## 三、根因分析

### 3.1 提示词「存了又没」

用户原话：「我群服互通里面的提示词，他好像不会保存吧，我保存了之后，后面我返回看了一下，唉，提示词没了」。

提示词只有一个字段：`assistant.prompt`，页面上有两个输入框写它：

| 面板 | 输入框 | 保存函数 | 后端 |
|---|---|---|---|
| 人设与试跑 | `#yyq-prompt` | `yyQQSavePersona`（console.js） | POST /api/qq/config |
| 群服互通助手 | `#yy-qq-ai-prompt` | `yyQQAssistantSave`（assistant.js） | POST /api/qq/config |

**线上版（box 127.0.0.1:19429 实际下载的两个文件）的 bug**：

1. box 版 `youyuan_qq_console.js` `yyQQSavePersona`：
   ```js
   var r = await A("POST", "/api/qq/config", { assistant: { prompt: prompt, model: model } });
   ```
   两个字段都从 DOM 整段读、整段回传。`model` 下拉在模型列表未回来时是空串——**顺带把已保存的模型也清掉**。
2. box 版 `youyuan_qq_assistant.js` 的 draft 固定包含 `prompt: v("yy-qq-ai-prompt")`——即**页面载入时的旧快照**。

于是：在 A 面板存好提示词 → B 面板输入框还是旧值（多半是空）→ 在 B 面板点任何保存 → 空串覆盖刚存的内容。用户看到的就是「存完再进来就没了」。**box 线上实证**：`GET /api/qq/config` → `assistant.prompt = ''`（用户确实丢了）。

**本地源码的修复**（本轮验证其正确性，未改动）：
- console.js:1568-1613 `yyQQPromptDraft` 单一草稿：任一框打字即记草稿并镜像到另一个框；保存只用脏字段（`yyQQPromptPatch`：没编辑过就不发 prompt，`yyQQModelDirty` 控制 model）；保存成功 `yyQQPromptSync` 清草稿、双框+双快照+折叠标题全部对齐，并回调 `window.yyQQAssistantPromptSync` 更新助手面板快照。
- assistant.js:482 `yyQQAssistantDraft`：仅当 `yyQQPromptDirty()` 才带 `prompt`；保存成功后同样走 `yyQQPromptSync` 对齐。
- 后端契约（youyuan_qq.go `yyMergePatch`，本轮加测试锁定）：`{assistant:{promot:...}}` 只打 prompt 补丁时**深合并保留** `model`/`mcp_url` 等兄弟字段；显式传空串才是清空。

### 3.2 `/api/qq/persona` 404 的真相

- 主控证据属实：box 上 `curl /api/qq/persona` → `{"error":"not_found"}`，且 `/var/lib/youyuan/qq-persona.json` 不存在（本轮复核确认）。
- 但**前端零调用**：本地 `frontend/` 全量 grep `api/qq/persona` = 0 处；box 线上实际服务的 6 个 qq js（console/assistant/config/guard/knowledge/memory/qq_bridge）逐一 grep 也是 0 处。
- 结论：`yyQQPersonaRoutes` 注册是「把死代码接上线」，接口本身现已可用（本轮 curl + 测试全链验证）；人格卡默认值（老白+13 条反AI腔）在内存中生效，自然语言禁令会把 taboos 写进它并落盘。用户诉求不依赖此接口，故本轮**没有**去改前端保存按钮的指向——改了反而会把提示词存到错误的地方。

### 3.3 违规词「不能改不能删」

用户原话：「甚至有些东西还不能删掉 比如违规词 不能修改」。

**线上/本地 `youyuan_qq_moderation.js` 交互函数 diff**（box 实际下载 vs 本地源码）：

| 能力 | 线上版 | 本地版 |
|---|---|---|
| 规则 添加 | ✅ yyMAdd | ✅ |
| 规则 删除 | ✅ yyMDel（带 confirm） | ✅ |
| 规则 启停 | ✅ yyMToggle | ✅ |
| **规则 编辑** | ❌ 无 | ✅ yyMEdit/yyMEditInput/yyMSaveEdit/yyMCancelEdit（行内编辑，回车保存） |
| **AI 长期禁令 增** | ❌ 无 | ✅ yyMTabooAdd/yyMTabooInput |
| **AI 长期禁令 改** | ❌ 无 | ✅ yyMTabooEdit/yyMTabooEditInput/yyMTabooSaveEdit/yyMTabooCancel |
| **AI 长期禁令 删** | ❌ 无 | ✅ yyMTabooDel（带 confirm） |

线上版规则只能删不能改、AI 长期禁令整块只读——与用户吐槽逐字吻合。

后端能力（本轮验证，无需改动）：
- `POST /api/qq/moderation {rules:[...]}` 整表替换（增/删/改都是「读全表→改→写回」）；`rules`/`taboos` 均为指针字段，只传一个不动另一个（防「只存禁令把规则表清空」的旧坑）。
- `DELETE /api/qq/moderation?pattern=&kind=` 按唯一键（pattern+kind）删一条。
- taboos 走 `yyQQPersonaSetTaboos`：空词条丢弃、重复只留一条、超 12 条/超 40 字裁剪。
- **编辑后立即生效**：`yyQQModerationReplace` 持锁改内存规则表即落盘，`yyQQModerationBlockHit` 实时读内存，无需重启/reload（有测试锁定）。
- 前端校验：空匹配内容、正则编译错误、重复词条（pattern+kind 相同）、禁令空内容/重复/超长，全部 `flash` 红字提示；删除一次 `window.confirm` 确认，不啰嗦。
