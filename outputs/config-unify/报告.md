# 配置统一化：模型配置（语言/画图/语音）+ 掉线智联

## 已完成

- **统一模型配置真的只有一份凭证**：`ai_models.json` 从裸数组升级为 `{version, models, roles}`（旧数组格式照读，不丢数据）。`roles` 只存「语言/画图/语音分别用模型库里的哪一条」，地址与密钥仍只在模型库里填一次。
- **复用 `/api/ai/models` 而不是新造 `/api/mcort/models`**：`GET` 现在同时返回 `models` 与 `roles`（含每个用途解析到的 model_id / 是否 ready）；`POST` body 带 `roles` 走用途保存，不带仍走模型增改。故**没有新增路由**，不需要再动 `yyAPIRoutes`/`yyMCPReadPaths`/`mux.HandleFunc`（只用 `youyuan_catalog.go` 补登了本来漏登记的 `/api/qq/watchdog`）。

- **老用户自动迁移**：roles 为空且群服互通已选过模型时，首次 `GET /api/ai/models` 自动把 `assistant.model/image_model/voice_model` 搬进 roles（不覆盖用户后来在统一配置里的选择）。
- **设置页新增「AI 模型统一配置」卡片**：三个下拉（对话/画图/语音）+ 出图尺寸 + 音色 + 语音模式，旁边「管理模型库」直接开原有模型库弹窗。群服互通卡片上加了指引，不再让人去那边配模型。
- **掉线智联开放修改**：设置页新增「掉线智联（掉线自愈）」卡片，开关 + 探测间隔（10–3600 秒）+ 每小时重启上限（1–100 次）可改，保存后重新 GET 回填。
- **验收**：`go build -o /tmp/models.exe .` 通过；两个前端文件 `node --check` 通过；另跑了一个临时全链路用例（详见第四节）确认「保存→回读→写穿」三段都成立，跑完已删。

## 二、统一后的数据结构

`<dataDir>/ai_models.json`（写盘 `version:2`；读到旧裸数组会自动兼容）：

```json
{
  "version": 2,
  "models": [
    { "name": "我的 DeepSeek", "provider": "openai", "base_url": "https://api.deepseek.com",
      "api_key": "sk-…", "model_id": "deepseek-flash", "thinking": "off", "streaming": true }
  ],
  "roles": {
    "language": { "model": "我的 DeepSeek" },
    "image":    { "model": "硅基流动·Kolors", "size": "1024x1024" },
    "speech":   { "model": "TTS·alloy", "voice": "alloy", "mode": "auto" }
  }
}
```

- `roles.*.model` 是**指向 `models[].name` 的引用**，不是第二份凭证：换密钥只改模型库里那一条，三个用途同时生效。
- `mode` 只允许 `off / auto / always`；`size` 必须 `宽x高`（64–4096）；引用不存在的模型名直接报错，不会写进半套配置。
- 写穿目标：`qq-bridge.json` → `assistant.{model,image_model,voice_model,voice_voice,voice_mode}`；`qq-image.json` → `{provider,model,base_url,api_key,size,models[]}`（`cloudflare` 与 OpenAI 兼容按 base_url / `@cf/` 自动判别）。

## 三、掉线智联为什么改不了（根因）

- **表象**：`frontend/js/youyuan_qq_console.js:432-448`，「重连次数上限」「间隔（秒）」两个 input 写死了 `disabled`，「保存」按钮也是 `disabled`，提示语写着「后端待支持：当前由服务端固定为每小时 3 次、60 秒探测一次」。上方注释（:432-434）也声称"后端没有对应字段"。
- **真相**：后端**早就支持**。`youyuan_qq_watchdog.go:279-315` 的 `POST /api/qq/watchdog` 接受并校验 `interval_seconds`（10..3600）与 `max_restarts`（1..100），`yyQQWatchdogConfigure`（:71）写进 `qq-bridge.json` 并落盘；`GET` 也把这两个值返回（:243-250）；`yyWatchdogTuning`（:45）每轮探测都重新读。
- **结论**：既不是只读，也不是服务端写死，是**前端把控件写死 + 注释/文案过期**。注释里"后端待支持"是历史遗留的错误判断。
- **我的处理**：那个文件不归我，我没动；在设置页（`youyuan_settings.js`）新增了可编辑的「掉线智联（掉线自愈）」卡片，走同一个 `GET/POST /api/qq/watchdog`，并把漏登记的 `/api/qq/watchdog` 补进 `youyuan_catalog.go:171`。控制台那处仍需负责它的 agent 把 `disabled` 与过期文案去掉（见第六节 3）。
