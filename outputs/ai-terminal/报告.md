## 掉线智联的根因

不是后端不支持，是前端自己把路堵死了：

- 后端 `youyuan_qq_watchdog.go` 早就实现了 `interval_seconds` / `max_restarts`：`yyWatchdogTuning()` 读配置并夹到 10..3600 秒、1..100 次，`yyQQWatchdogConfigure()` 落盘 `qq-bridge.json`，`yyWatchdogStatus()` 也一直回这两个字段，探测循环每轮重读配置（改完不用重启进程）。
- 前端 `yyQQWatchdogBox()` 却：读 `w.max_per_hour`（旧字段）、间隔写死 `60`、两个 input 加 `disabled`、保存按钮加 `disabled`，还挂一行「后端待支持：当前由服务端固定为每小时 N 次、60 秒探测一次」。
- 结果：用户看到的是「后端不给改」，实际是前端拿旧字段渲染 + 硬禁用，且那句说明本身就是错的。

现在：值来自 `w.max_restarts || w.max_per_hour`、`w.interval_seconds || 60`，保存前按后端同样的区间（1–100 / 10–3600）校验，失败原样回显后端错误，成功后 `yyQQPollLogin(1)` 立刻回读。

## 多群聊布局方案

```
[状态带 · sticky]
[快捷跳转 chips]
[身份卡：头像 / 昵称 / QQ号 / 游戏身份 / 今日动作 / 掉线自愈]
┌───────────────┬─────────────────────────────────────┐
│ 能力矩阵       │ 消息面板                             │
│ （含技能折叠）  │  ┌ 群标签横滑：[亲友群][工作群 3][…] 实时 ┐│  ← 28px，一行，超宽横滑
│               │  ├ 时间线（单一列表，内滚）             ││
│               │  │        [小明] 在吗            ← 左   ││
│               │  │   点赞 · 小明 已点赞  (小灰字)        ││
│               │  │   [机器人] 在的 →             → 右   ││
│               │  ├ 刷新                                ││
│               │  └ 以机器人身份发送 [____] [发送]      ││
└───────────────┴─────────────────────────────────────┘
[折叠区：接入与互通群 / 人设与试跑 / AI 工具 / 收藏表情]
```

- 窄屏（≤1180px）单列时消息面板 `order:-1` 排到能力矩阵**前面**，群标签跟着上移。
- 群标签的就地滚动位置在每次重绘（30s 一次）后还原，并保证当前标签在可视区内；切群/发消息时时间线强制贴底。
- 接入区改多选：群卡片可同时勾多个（`yyQQC.sel`），保存时未勾的群保留成 `enabled:false`（不删配置、不丢群名）。
