## 一、not_found 根因（有实测）

链路，四步：

1. 前端旧版第 59 行打 `A("GET","/api/qq/rag/stats")`（同文件还有 `/api/qq/rag/docs`、`/api/qq/usage/context`）。
2. `/api/qq/rag/*` 的注册函数是 `yyQQRagRoutes(mux, dataDir)`，`youyuan_qq_rag.go:1233`；同文件 1231 行注释自己写着「**只定义不注册，由主智能体在 yyRegisterQQ 里调用**」。
3. 全仓 grep `yyQQRagRoutes` 只有三处：自身定义、注释、`youyuan_qq_rag_test.go:355`（测试）。**生产零调用**。
4. 于是请求落到 `main.go:268 handleIndex` 的 `/api/` 兜底：

```go
// main.go:268-273
if strings.HasPrefix(r.URL.Path, "/api/") || r.URL.Path == "/api" {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(http.StatusNotFound)
    writeJSON(w, map[string]any{"ok": false, "error": "not_found", "path": r.URL.Path})
}
```

前端 `A()`（`frontend/js/api.js:50`）原样返回这段 JSON，面板又把 `stats.error` 直接显示 → 用户看到的整块内容只有 `not_found`。**不是文档仓库为空**（那种情况 `stats` 会是 `{docs:0}` 而不是 404），**也不是前端路径拼错**（路径与后端函数内注册的路径逐字一致）。

实测（本地临时数据目录、httptest 打真实 mux，未动线上进程、未占端口）：

```
[1 旧路径 rag/stats] HTTP 404 {"error":"not_found","ok":false,"path":"/api/qq/rag/stats"}
```

复现命令（部署后可直接打）：`curl -s -o- -w ' %{http_code}\n' http://127.0.0.1:<port>/api/qq/rag/stats`

## 三、上传限制值（写死在后端，前端同样预检）

| 项 | 值 | 超限文案 |
|---|---|---|
| 单文件 | 4 MiB（`yyKBMaxFileBytes`） | 「文件超过 4.00 MB 上限，请拆分或压缩后再传」 |
| 单篇正文 | 1 MiB（`yyKBMaxTextBytes`） | 「正文 X 超过单篇 1 MB 上限，请拆成几篇再传」 |
| zip 条目数 | 200 | 「压缩包里超过 200 个文件，请先挑出需要的再传」 |
| zip 解出文本合计 | 8 MiB | 「压缩包解出的文本超过 8.00 MB，请分批传」 |
| zip 单条目 | 1 MiB | 静默跳过并计入 `skipped` |
| 扩展名白名单 | `.md .txt .json .csv .zip`（zip 内另认 markdown/tsv/log/yml/yaml/ini） | 「只支持 .md/.txt/.json/.csv/.zip，收到 .exe」 |
| 二进制判定 | 前 8 KiB 含 NUL 或整体非合法 UTF-8 | 「这个文件不是纯文本（含二进制字节）…请导出成 .md/.txt 再传」 |

zip 走 `archive/zip` 逐条读、`io.LimitReader` 兜住单条，只抽文本，**二进制永远不进库**（实测压缩包里 1 个 png 被跳过：`{"added":1,"skipped":1}`）。

## 六、留给下一手的坑

- **群聊 RAG 注入仍是空的**：`yyRagSearchAuto` / `yyRagPromptBlock` / `yyRagIngestChat` 零调用，AI 现在读不到知识库。接的时候注意 `yyRagEnabled` 要 `assistant.memory.enabled=true` 才放行，而知识库面板的读写**故意不**吃这个开关（否则用户上传会吃到 `rag_disabled`）。
- 并发风险：`yyRag` 内存表由 `youyuan_qq_rag.go` 持有，我只用它的 `Lock` 和自己的 `yyKBState`，没有反向持锁，不会死锁；但**谁都不要再调 `yyRagInit`**。
- 中文文案：全程没用 sed。知识库 JS 是整体重写（整文件都属于知识库），没有做局部中文替换，所以没走 `replace_cn`；后续若只改一两句文案，按约定用 `replace_cn(path,[(旧,新)])`。
- 术语对齐：本报告「玩家」=游戏内角色，「用户/群友」=QQ 侧的人，「账号」=工具箱登录账号；面板上传按「用户/群友」的能力描述，未做玩家侧入口。
