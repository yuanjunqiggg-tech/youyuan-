## 二、严重（功能失效 / 后改的踩掉先改的）

### S1　设置页被三套实现同时定义，15 个 id 完全相同
- `js/pages/settings.js:15`（`Rcfg` 首版）
- `js/youyuan_dashboard.js:127`（`Rcfg=async function`，整套重写）
- `js/youyuan_settings.js:28`（`Rcfg=async function`，再整套重写）
- 三者共有 id：`bot-server`、`bot-pass`、`cfg-token`、`cfg-conn-card`、`cfg-conn-st`、`cfg-speed`、
  `cfg-theme-picker`、`cfg-fleet-conn`、`cfg-fleet-status`、`cfg-multi-card`、`cfg-acc-card`、
  `cfg-sub-token-list`、`cfg-token-add`、`cfg-server-picker`、`cfg-verif-btn-wrap`（共 15 个）
- 后果：settings.js 与 dashboard.js 两套是死代码（#11 → #47 被 #48 覆盖），但 42/61 个同义 id 继续
  被其它文件按旧结构 getElementById；任何一次回滚/重排加载顺序都会让"另一套"复活。
- 这是"有概率显示另一种"的结构性温床：三份 DOM 契约，只要生效者换人，页面就是另一个样子。

### S2　`Rcfg` 被 18 处定义/接管，其中 2 处是无条件替换（不接前版）
- 无条件替换（丢掉前一版）：`js/pages/settings.js:14`、`js/youyuan_dashboard.js:127`
- 正确包裹（`await base.apply(this,arguments)`）：`youyuan_social.js:3`、`youyuan_appearance.js:12`、
  `youyuan_usability.js:5`、`youyuan_sense.js:2`、`youyuan_identity.js:345`、`youyuan_identity.js:438`、
  `youyuan_game_auth.js:263`、`youyuan_game_auth.js:380`、`youyuan_connection_policy.js:179`、
  `youyuan_connection_diagnostics.js:157`、`youyuan_global_capture.js:80`、`youyuan_room_discovery.js:323`、
  `youyuan_settings_groups.js:81`、`youyuan_game_controls.js:37`、`youyuan_navigation.js:19`
- 最终生效：`js/youyuan_navigation.js:19`（外面套了 16 层）
- 具体风险：`youyuan_dashboard.js:127` 版没有 settings 版的 `epoch/scope` 守卫（`live()`），只有
  `curTab==='settings'` 判断；一旦加载顺序变动让它成为基底，切页竞态会往已卸载的 DOM 写。

### S3　`showAlertModal` 两套签名，后加载者全局生效
- `js/utils.js:304`：`(title, msg, closeable, onClose, extraButtons, zIndex)` → 永远渲染"关闭"按钮
- `js/features/announcements.js:79`：`(title, body, canClose, onAction, actionLabel, zIdx, keepOpen)`
- 加载序 utils #6 → announcements #21，**全局拿到的是 announcements 版**
- 踩点：`js/features/mapart.js:480 / 494 / 496 / 500` 只传 2 个参数 → `canClose` 为 undefined →
  **弹窗没有关闭按钮**，只能点遮罩退出（utils 版是有按钮的）
- `js/pages/settings.js:94` 恰好传 6 个参数（第 4/5 为 null）侥幸兼容；任何用了 utils 版
  `extraButtons`（第 5 参）的调用都会被当成按钮文字渲染

### S5　重复 id `viewer` 会在同一容器里累积，getElementById 取到旧节点
- `js/app.js:245`、`js/features/building.js:424`、`:435`、`js/features/mapart.js:45`、`:95`
- 都往 `#imp-info` append 一个 `id="viewer"` 的 div；building.js:424/435 是同一函数的两个分支，
  mapart 同理。二次预览后 DOM 里出现 2 个 `#viewer`，`getElementById("viewer")` 返回第一个（旧的，
  尺寸/内容都是上次的）→ 3D 预览画到旧画布上。**这正是"有概率显示另一种"的典型形态。**
- 建议：id 只留一个，其余改 class 查询。

### S6　`RbuildingMgmtHTML` 三处覆盖，前两套是死代码
- `js/features/building_mgmt.js:38` → `js/youyuan_library.js:11` → `js/youyuan_settings.js:19`（最终生效）
- 首页 `js/pages/home.js:23`、仪表盘 `js/youyuan_dashboard.js:37` 都按 `RbuildingMgmtHTML()` 出页面，
  用户看到的是最后一版；building_mgmt 版里的"文件市场 / 贡献 / 批量"入口只剩按钮，页面结构已变。

### S7　新主题文件 `js/mcort_theme.js`（24 KB）根本没被加载
- index.html 的 109 个 `<script src>` 中无此文件；全项目也无 `mcort_theme` 引用
- 文件内只导出 `window.mcortTheme`，无人调用 → 24 KB 纯死代码，主题框架实际未生效

### S8　2 个文件版本号落后于 mtime，浏览器会命中旧缓存
- `js/youyuan_settings.js`　`?v=2026102520`（L130），mtime 2026-10-26 → 差 1 天
- `js/youyuan_global_capture.js`　`?v=2026102520`（L174），mtime 2026-10-26 → 差 1 天
- 其余 147 条引用的版本号是 `20261028xx`（比 mtime 新），不构成"取旧"风险，但说明版本号是批量刷的、
  并非按真实修改时间生成，失去比对意义。

## 三、一般（体验差 / 隐患）

### G1　`cfgToken` 同名全局声明两次
`js/app.js:7` 与 `js/pages/settings.js:1` 都 `var cfgToken=""`。settings #11 先执行、app #29 后执行，
后者的初始化会把前面写入的值重置为空字符串。当前两者写入都在函数内，未触发实害，但顺序一变就丢 token。

### G2　`updateURL` 同名全局声明两次
`js/features/announcements.js:3` 覆盖 `js/pages/settings.js:3`。settings 侧此后无人读写（死变量），
OTA 下载只认 announcements 那份；两处同名不同义，后续谁改都可能踩到对方。

### G3　QQ 模块之间互相覆盖（设计如此，但只剩最后一个生效）
- `yyQQRenderAll`：7 个文件包装（assistant:789 / console:2386 / config:838 / knowledge:407 /
  serverinfo:735 / guard:198 / moderation:597），每层都有 `__yyXWrapped` 守卫，**当前是健康的**；
  但任何一处漏掉守卫就会双渲染，同一面板出现两份内容。
- `yyQQRefreshAll`：`youyuan_qq_console.js:2562` 覆盖 `youyuan_qq_assistant.js:565`
- `yyQQAssistantSave`：`youyuan_qq_member_ui.js:320` 覆盖 `youyuan_qq_assistant.js:633`
- `yyQQRefreshMembers`：`youyuan_qq_member_ui.js:432` 覆盖 `:300` 与 assistant:569

### G4　皮肤库 5 个函数被新文件整体覆盖（按注释是刻意 override）
`youyuan_accounts.js` 定义 → `youyuan_skin_library.js` 覆盖：
`yySkinLibraryTargetRow`(acc:1810/skin:43)、`FetchTexture`(1851/67)、`SyncReal`(1907/111)、
`Entries`(1934/147)、`Open`(1964/291)、`Render`(2009/170)。旧实现仍留在 accounts.js 里（约 200 行），
两套并存，排查问题时极易看错实现。

### G5　`__subPageRestoreHooks` 被 5 个文件写
`building_mgmt.js:52`、`plugin_market.js:53`、`youyuan_accounts.js:1569`、`youyuan_identity.js:539`、
`youyuan_agent_layout.js:17` —— 全部是 `= window.__x || []` 再 `push`，安全；仅记录为共享可变状态。

### G6　31 个 `.esb` 旁路文件与主文件同目录同名
如 `js/app.js.esb`、`js/pages/settings.js.esb`、`js/features/building.js.esb`。均未被 index.html 引用，
但和生效文件只差一个后缀，很容易被误改（本次扫描已确认它们不参与运行）。

## 五、建议修复顺序（按性价比）
