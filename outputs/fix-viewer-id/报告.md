## ② 修法与改动位置

### 1) viewer 拆 id（唯一化）

| 场景 | 新 id | 文件:行 |
|---|---|---|
| 恢复缓存时补建的容器 | `viewer-app` | app.js:250 |
| 建筑导入预览 | `viewer-building` | building.js:424、435（创建）、444（读取） |

配套（关键，光改 id 不够）：
- app.js:34-36 `yySnapshotSubPage` 由 `querySelector("#viewer")` 改成 `querySelectorAll(".viewer")` 全删——否则页面里有两块画布时缓存仍会漏掉一块。

- CSS 未受影响：样式选择器是 `.viewer`（components.css:255），没有 `#viewer` 规则。

### 2) showAlertModal 统一签名

选的方案：**保留 utils.js 作为唯一实现，announcements.js 改成转发**（不是“新版兼容 2 参”）。
理由：三个真实调用方（announcements / notifications / settings）都是 7/6 参的“标题+正文+是否可关+动作回调+动作文案+zIndex”，只有 mapart 是 2 参；把唯一实现放在 utils.js 能保证“谁后加载都不改变语义”，而只做兼容层仍然留着两份实现，下次再改必再踩。

- utils.js:303-349：新 `yyShowAlertModal(title, body, canClose, onAction, actionLabel, zIndex, keepOpen)`
  - `canClose` 省略 → 按 `true`：mapart 的 2 参调用现在有「关闭」按钮。
  - 无动作按钮且 `canClose=false`（如 showIntegrityAlert）→ 仍然给「关闭」，避免弹窗无路可退。
  - 有动作按钮但 `canClose=false`（强制更新）→ 只留动作按钮，且不再允许点遮罩关闭（原来能点掉，等于绕过强制更新）。
  - 关闭/动作按钮改用 `querySelector` 取，不再全局 `getElementById("alert-close-btn")`（两个弹窗同时存在时会拿错节点）。
- announcements.js:79-84：只保留同名转发 `return yyShowAlertModal(...)`。
- 未改动任何调用点（mapart 2 参、announcements 7 参、notifications 6 参、settings 6 参全部继续有效）。

### 3) Rcfg：谁在覆盖谁

真相：`pages/settings.js` 的 `Rcfg` 被 youyuan_dashboard.js 整份替换，dashboard 又被 youyuan_settings.js 整份替换；之后全是“取旧值再包装”的 wrapper。最终 = `youyuan_navigation` 最外层 → `youyuan_game_controls` → … → `youyuan_settings`。

本次改动（只在我名下这份）：settings.js:26 `async function Rcfg()` → `RcfgLegacy()`；settings.js:815-816 末尾挂 `window.RcfgLegacy = RcfgLegacy` + `if (!window.Rcfg) window.Rcfg = RcfgLegacy`（保留“脚本缺失时兜底”的旧行为，不删除）。
运行时行为不变（它本来就没被调用过），但这套 15 个同名 id 的实现从此不会再因为同名而“看起来是它在渲染”。

不删除的依据：文件里 `refreshCfg / refreshCfgAccount / saveCfg / doConn / doDisc / doSearch` 等函数仍被 live 页面调用，删函数体风险高。

**未修（不在我名下，需要你点头才能改）**：
- `youyuan_dashboard.js:127` — 死代码，建议同样改名 `RcfgLegacyDashboard`；注意它自带 `_cfgRefreshTimer` 定时器，改名后不会再有第二个 10s 轮询。
- `youyuan_settings.js:25` — 这是**真正在用的打底实现**（后面 13 层都 `await` 它），不要动。
