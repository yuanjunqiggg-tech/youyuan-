# MCORT 账号卡响应式布局修复报告

日期：2026-10-26 · 范围：仅 `frontend/css/youyuan_accounts.css`（另两个文件已核查，无需改动）

## ① 三个缺陷的修法

### 缺陷 1：601–1023px 没有定宽，状态列 `auto` 逐行漂移
- **改法**：新增 `@media(min-width:601px)` 块，把原来只在 ≥1024 生效的四条定宽列提前到 601 起；同时把状态列从 124 加到 132（最长文案实测需 125px，原 124 只剩 −1px）。
  - `youyuan_accounts.css:56-59`（新增块，`:57` 为 `44px minmax(0,1fr) 132px 14px` + `column-gap:12px`）
  - `youyuan_accounts.css:295`（≥1024 原 124 → 132，保持全档同宽）
  - `:48` 的 `auto` 保留为 600 以下的兜底（≤600 已由 `:52` 覆盖，不会再命中）
- **结果**：800px 下六行状态列左缘漂移 **81.9px → 0**，601/660/700/900/1000/1023 全部 0。

### 缺陷 2：桌面皮肤控制条 156px 塞进 112px 列，必然折两行
- **改法**：形象列 112 → **168px**（156 + 12 余量），立绘框同步放宽到 168×196（人形仍居中、像素比例不变，`unit` 由 `min(w/23,h/38)` 计算，只多出左右留白）；控制条 `flex-wrap:wrap → nowrap` 并加 `max-width:100%`，永不折行也不撑破列。
  - `youyuan_accounts.css:92`（`.yy-acct-hero` 列宽 168）
  - `youyuan_accounts.css:93`（`.yy-acct-figure` 168×196）
  - `youyuan_accounts.css:190`（`.yy-acct-figure-col{width:168px}`，原 112）
  - `youyuan_accounts.css:192`（`.yy-acct-skin-bar` nowrap / max-width）
  - `youyuan_accounts.css:303`（≥1024 的 hero 列宽 112 → 168，否则桌面又被压回去）
- **结果**：控制条高度 70px（两行）→ **32px（一行）**，宽度 112 → 168，左缘与立绘左缘重合（800/1024/1440 均为 30/198、32/200）。

### 缺陷 3：移动端状态列 ≤78px，最长状态被砍
- **改法**：≤600 状态列 `minmax(50px,78px)` → **110px 定宽**；`.yy-compact-status` 去掉 `max-width:118px` 的夹击，`line-height:1.35`。文案不截断、不右对齐吃字，必要时才换行（实测最长串 104px 在 110px 内单行放得下）。
  - `youyuan_accounts.css:52`（`36px minmax(0,1fr) 110px 9px` + `.yy-compact-status{font-size:10px;line-height:1.35;max-width:none}`）
- **结果**：320/360/390/430/600 全部 **1 行、溢出 0px**（原 78px 时同一串折成 2 行）。

### 附加：360px「走动/纤细/正视角 太下面」
- 移动端立绘框 164 → **158px**，3D 模型基线 `top:48% → 50%`（上下留白由 13.9/21 变为 13.9/14.8，人形居中不再「往右下坠」），脚底到控制条的距离 **31px → 25px**，整块上移 14px。
  - `youyuan_accounts.css:161`（`.yy-acct-figure{width:92px;height:158px}`，占位图 44×88）
  - `youyuan_accounts.css:107`（`.yy-acct-figure-stage .yy-skin-model{top:50%}`，双类名压过 JS 注入的 `.yy-skin-model{top:48%}`，无需改 `youyuan_skin_viewer.js`）
- **结果**：320/360/390/430/600 控制条 `bottom=208.4 ≤ 800`、`right=338 ≤ 360`，完整可见未被裁。

### 未改动的两个文件（核查结论）
- `frontend/js/youyuan_skin_viewer.js`：模型 `top/left` 由 CSS 控制，用 CSS 选择器覆盖即可，脚本无需改动。
- `frontend/css/youyuan_account_pool.css`：`.yy-pool-row` 是 `minmax(0,1fr) auto` 的另一套组件，不含 `.yy-account-summary`/`.yy-acct-*` 规则，三处缺陷都不落在它身上；全仓 CSS 也没有对 `.yy-acct-hero / .yy-acct-figure / .yy-account-summary / .yy-acct-skin-bar` 的第二份覆盖。

## ③ 还不理想的宽度

1. **601–1023 行高 68px，比 ≥1024 的 64px 高 4px**：这一档沿用原 `min-height:68px`，四条对齐线不受影响，但和桌面卡切换时会有 4px 的视觉跳变。若要完全一致，把 `:57` 补上 `min-height:64px` 即可（怕影响平板点按面积，本轮没动）。
2. **320px 名字列只剩 97px**（360 为 137px）：状态列 110px 是「不砍字」的硬需求，代价压在名字上，长名只能省略号。320 属于极端窄机，未再压缩头像（36px 已是下限）。
3. **状态列宽是为最长文案硬留的**：「内核在线 · 游戏未连接」在 10px/12px 字号下实测 104/125px，故取 110/132。以后若再加更长状态（如「内核在线 · 游戏未连接 · 重连中」），≥601 会折成两行（行高变 68→82）、≤600 会断行，届时需要改文案或改列宽。
4. **箭头 `›` 的盒子宽 33px，超出 9px/14px 的列轨道约 2px 被卡片 `overflow:hidden` 切掉**（各宽度都存在，属预置行为，非本轮三项缺陷）；视觉上箭头落在卡片内边距里、不影响四条对齐线，本轮未动。
5. **形象区从 112 加宽到 168，右栏少 56px**：1024 下右栏仍有 550+，三个动作按钮 + 令牌行不换行、无溢出；但 601–700 区间右栏只剩约 390，按钮会折行（原本也会折），体验一般——这是「控制条单行不折」必须付的代价。
