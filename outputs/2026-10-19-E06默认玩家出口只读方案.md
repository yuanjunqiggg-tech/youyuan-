## 最小完整方案

1. 明确三种执行位置。手机原生 APK 本机运行机器人时可以使用手机原生 UDP；Linux 云端运行机器人时必须有玩家设备上实际发出 UDP 的 agent；普通浏览器不能仅通过网页 HTTP/中继地址实现任意原始 UDP 出口。
2. 增加 player 模式并作为新连接的默认意图，绑定当前平台账号、本人已授权设备及具体机器人会话。Android foreground service 保持玩家 agent 在线；它从自己的真实网络拨号并持有 UDP socket。云端与手机使用带认证和会话隔离的加密反向数据通道，手机端执行 UDP dial/read/write。可沿用已有控制连接的设备认证与撤销策略，游戏数据使用独立有界队列与流控，避免与管理通道争锁。
3. 在现有 `GameUpstreamDialer` 接入 player UDP 传输，保留完整 datagram 边界、目标地址、取消、deadline、关闭和大小上限。Linux 只把数据交给该会话的手机 agent；手机离线、未配对或未授权时返回明确 unavailable，不能静默退回 Linux system 后仍显示玩家节点。
4. 官方节点保持可选；官方模式若使用官方目的节点但仍经执行设备出站，应分别记录官方目的节点与实际出口设备。已有SOCKS5 UDP作为高级自有节点保留，授权及密码私存规则继续使用。
5. 本地房间额外覆盖 RakNet/信令/WebRTC 的实际 dialers。仅给租赁服/联机大厅 UDP 注入 UpstreamDialer 不会自动覆盖本地 WebRTC。若暂未实现，player+local 继续明确 unsupported，不把某次HTTPS信令可达当作WebRTC游戏出口通过。
6. 配置和状态合同区分 `requested_mode`、`actual_route_scope`、`device_id`（公开脱敏标识）、`association_state`、`last_heartbeat`、datagram counters、`public_ip_verified` 和 `verified_game_session`。页面默认“玩家设备节点”，显示当前绑定设备；无可用设备时提示先连接本人的设备，不能自动选其他租户或机器人节点。

## 完整验收门槛

- 本地协议测试：数据报边界、乱序/丢包、队列上限、取消、超时、双向关闭、同账号多机器人隔离、跨租户拒绝、租约/撤销立即失效；仅内存 mock 不构成真实出口验收。
- 真实手机与真实Linux同时在线：获授权受控 UDP echo 端以服务器日志证明包来自手机出口公网地址，且与 Linux 直出地址区分；收发成功并读回实际 route/device 标识。
- 真实游戏：从 Linux 机器人经手机节点登录受控目标，检查双向 RakNet 数据与真实游戏可用状态；不能只测 SOCKS5 ASSOCIATE 或 TCP/HTTP。
- 断开手机/切网络/后台恢复：会话明确失败或按用户已启用重连策略恢复，取消可停止；没有未经同意的系统出口回退。
- 分别验收租赁服、联机大厅、@本地房间 WebRTC。三种结果不得互相替代。

该方案描述尚未执行的必要工作。本轮没有将当前 Linux system UDP 记为手机出口，没有更改默认设置，也没有声称 E06 完成。
