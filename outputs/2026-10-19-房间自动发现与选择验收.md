# 房间自动发现与选择：源码及本地验收

时间：2026-10-19。负责范围：E01/E02 的连接候选发现、显示及选择合同。本文不修改版本和总账，不宣称整体完成。真实凭据、统一构建、部署及真接口验收由 root 接管。

## 已实现

- 短号码（含 `#11451` 和 `@11451`）查询前去掉显示前缀，依次调用现有的 `SearchRentalServerByName`、`SearchOnlineLobbyRoomByKeyword` 和 `GetTransferRoomWithName`。不把短号强制解释成完整 `room_id`；不新增仿造的发现接口。
- 服务端响应聚合 `candidates`、每个来源 `sources`、`complete` 和 `read_only`。某来源报错、仍有分页、来源不齐或候选校验失败时不能成为“完整唯一候选”。错误类别保留；不将上游可能带敏感内容的原始错误体写日志或公开响应。
- 前端只显示非空类别；同号四个候选可显示租赁 1、联机 2、本地 1。卡片只使用接口真正提供的名称、房主姓名或 UID、封面、在线/容量和版本。人数缺失时不填 0；真实 0 保留。头像/封面缺失时不生成默认人物图。
- 只有完整查询且一个候选才自动选择并连接；多个候选由用户明确选择。部分成功时即使只发现一个，也保留确认按钮，不自动连接。查询本身不调用游戏登录、不断开当前机器人、不修改自动重连或创造开关。
- 选择提交必须属于相同凭据、认证地址、原始输入绑定下五分钟内的候选快照。客户端不能直接提交任意 target。持久文件为当前账号数据根的 `room-choices.json`，权限 0600；键为 token/auth/query 的 SHA256，最多 64 条，不保存 token 或认证 header。
- 输入未变且凭据/认证地址相同，下次连接复用已选择 target。输入改变或凭据/认证地址不同不会命中。设置页面重开时可从已选择 target 恢复原输入。`handleBotConnect` 在 normalize 前也复用已保存选择，后续 SDK 接收的是 `LobbyGame:room_id=<完整ID>`、`@<本地RID>` 或租赁号码；长 ID 始终使用字符串。
- 输入变化或查询返回过时会丢弃结果，不发连接请求。发现列表没有选择即可离开；只有按“选择并连接”才发起连接。明确完整房间 ID、山头邀请码和分享链接保留现有入口。
- 按 root review 已移除新增 JS 自己复制的连接/定时轮询，选择确认后只调用已捕获的原 `doConn`。输入保持原值，后端根据持久选择解析 target，继续复用已有连接弹窗、取消、状态与保活。
- 授权扩展了自有认证 `phoenix/tan_lobby_login`：根据本人 bearer 路由到原 vault，同账号串行重新核令牌，kernel 复用 FunAuth TanLobbyLogin；返回 SDK 需要的 snake_case 和 hex 字节字段。local 失败不执行自动重放，也不切换机器人或用户账号。
- 修复旧 TanLobby 查找默认取首项：数字 RID 和明确 ID 必须精准命中；传统按名称查找只能选择唯一的完整同名候选，重名或部分匹配均拒绝。房间查询和官方 transfer 服务发现使用同请求 context，12 秒 transfer 查询上限，不再依赖无界全局缓存锁。

## 待 root 复核与验收

1. 新增 kernel Go 文件要求重新构建 `auth-service/kernel.wasm`。当前本文的源码和本地测试不代表已部署或公网接口可用。
2. 真接口：`POST <认证地址>/api/game/discover`，Authorization Bearer 本人有效游戏令牌，JSON `{ "keyword": "#11451" }`。只读结果应核每个来源的 ok/count/more 与真实字段；无凭据调用不能变成平台管理权限。
3. delegated 认证基址已加入新发现路由，同时保留 grant 存活检查并要求传入的游戏 token 精确匹配 grant 的 owner/id/token_hash。其它第三方认证服务没有发现能力时会明确失败；不能假称全部认证提供商已适配。
4. 现有 TanLobby 登录仍会以所选 RID 回查 `/room-with-name`；已拒绝未命中时首项回退，回查不命中会明确失败。auth Worker→kernel→FunAuth 的静态调用合同和本地授权/编码/取消测试通过；没有真实本地房间查询/进服证据，不能证明官方回查必然命中或实际 RakNet/WebRTC 通道可用。
5. “重新查询”仅重新发现；若发现完整且唯一，按已授权的连接入口仍会自动连接。输入变化或离开页面时应在真实浏览器再验取消行为；DOM 回归已证明输入变化不会使用旧结果连接。
6. 真实 Web/Linux/APK 多租户及独立机器人需复核各自数据根、凭据绑定和卡片布局。公网、Android、真实联机房间、本地房间进服、长跑及协议 3.10 均未由本代理验收。

结论：源码实现和相应本地合同/DOM回归已通过；本轮没有使用真实凭据发请求，没有擅自让在线机器人换服。整体任务、真实发现与真房间进服仍待 root 集成验收。
