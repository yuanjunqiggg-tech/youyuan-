## 2. manifest 字段表（`<dataDir>/themes/<id>/theme.json`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 小写字母/数字/`.-_`，≤64，**必须等于目录名** |
| `name` | string | 是 | 展示名 |
| `version` | string | 是 | 主题版本 |
| `author` | string | 否 | 主题作者（与工具箱作者「疣螈」是两回事） |
| `mcort_theme_api` | int | 是 | 目前只接受 `1` |
| `requires` | []string | 否 | 仅允许 `theme-core / brand-guard / announcements / plugins / qq-console` |
| `variables` | map | 否 | 只能 `--mcort-theme-*`，值禁 `< > { } ; \ @import url( javascript:` |
| `slots` | map | 否 | 只有 `header / sidebar_footer / floating`；值是纯文本或 `assets/…`，禁 HTML |
| `remove_brand` | bool | 否 | **为 true 直接拒绝加载** |
| `hide_author` | bool | 否 | **为 true 直接拒绝加载** |

目录内必须有 `theme.css`；`theme.js` 可选（只做打包与审阅，不执行）；`assets/` 可选。

## 3. 可覆盖的 CSS 变量清单

配色：`--mcort-theme-primary`、`-primary-hover`、`-primary-active`、`-primary-bg`、`-on-primary`、`-bg`、`-bg-card`、`-border`、`-border-light`、`-text`、`-text-secondary`、`-text-disabled`
背景：`--mcort-theme-bg-image`、`-bg-size`、`-bg-position`、`-bg-dim`（0–1 压暗）
形状排版：`--mcort-theme-radius`、`-radius-sm`、`-radius-lg`、`-font-base`、`-font-sm`、`-font-lg`、`-gap`、`-shadow`、`-shadow-lg`
群服互通：`--mcort-theme-qq-primary`、`-qq-radius`、`-qq-font`

写法：manifest 的 `variables` 直接给值（如 `"--mcort-theme-primary": "#0af"`）；背景图与复杂样式写在 `theme.css`，服务端会把相对 `url(...)` 重写成 `/api/mcort/theme/asset?...`。布局钩子：`html[data-mcort-theme="<id>"]`，主题可据此写整体布局选择器。没有 `data-mcort-theme` 时不改写任何 `--phx-*`，出厂外观不变。

## 4. 硬编码守卫判定规则

先做归一化：去掉 `/* … */` 注释、转小写、去掉所有空白与引号（因此 `a{/*x*/display:none}`、`display : none` 都会被识破；纯注释里的字样不会误杀）。然后：

| 编号 | 规则 | 处置 |
|---|---|---|
| M1 | manifest `remove_brand: true` | 拒绝：MCORT 标识属于硬编码层 |
| M2 | manifest `hide_author: true` | 拒绝：作者署名属于硬编码层 |
| C1 | 出现 `--mcort-brand*:` 声明（含 `--mcort-brand-color:`） | 拒绝：试图重定义品牌变量 |
| C2 | `.yy-brand-mark` / `#mcort-brand` / `.mcort-brand-signature` / `[data-mcort-brand` 所在规则的声明块含 `display:none`、`visibility:hidden`、`opacity:0`、`font-size:0`、`height:0`、`width:0`、`clip:rect(0`、`left:-9999`、`content-visibility:hidden` | 拒绝：试图隐藏标识 |
| C3 | 同上选择器后 320 字符内出现 `.remove(`、`removeChild`、`style.display`、`visibility`、`innerHTML=`（针对 `theme.js`） | 拒绝：试图用脚本移除品牌节点 |

拒绝信息直接写清原因（如「拒绝加载：主题试图隐藏 yy-brand-mark（MCORT 标识与作者署名不可隐藏）」），该主题 `ok=false` 不出现在可选列表，前端也不会加载它。前端另有第二道：署名节点用 `id + class` 选择器 + 内联 `!important`，并在页面右下角/左下角固定；`MutationObserver` 发现被删就补回，另有 2 秒兜底轮询；`meta[name=mcort-author]`、`console` 与公告页页脚各再写一次署名。

## 5. 公告接口契约

`GET /api/mcort/announcements`（只读，已加入 `yyMCPReadPaths`）
→ `{ok:true, announcements:[…], admin:bool, brand:"MCORT · 作者 疣螈"}`；`announcements` 按置顶优先、时间倒序。

`POST /api/mcort/announcements`（写，需管理员）
请求：`{op:"create"|"update"|"delete", id?, title, content, severity:"info"|"warning"|"critical", pinned?:bool}`
成功：`{ok:true, announcement:{id,title,content,severity,pinned,author,created_at,updated_at}}`；删除返回 `{ok:true,deleted:"ann-…"}`。
失败：403 `{ok:false,error:"只有管理员可以发布公告"}`；其余 400/409 带中文原因。

约束：标题 ≤80 字、正文 ≤8000 字、最多 200 条、请求体 ≤32KB、原子写（`.tmp` + rename）。落盘 `<dataDir>/announcements.json`（`{version:1,items:[…]}`，0600）。管理员判定：绑定平台账号时看 `role=admin` 或 `legacy_owner`；未绑定时只信任本机回环地址。
前端：`/#announce`（以及 `#announce/theme`、`#announce/plugins`）全屏页；右下角「公告」挂件是入口；无权限时只读。

## 6. 主题与插件接口

`GET /api/mcort/themes` → `{themes:[{id,name,version,author,ok,error,variables,slots,has_css,has_js}], active, brand}`；
`GET /api/mcort/theme` → 当前主题详情 + `css_url`；`POST /api/mcort/theme {id}`（管理员，`id:""` 恢复默认）；
`GET /api/mcort/theme/asset?theme=&file=` → 只放行 `theme.css`、`theme.js`、`assets/**`，≤4MB，CSS 出站前重写相对 `url()`；
`GET /api/mcort/plugins` → 发现 `plugins/<id>/{plugin.json,main.js}`；`POST {op:"enable"|"disable",id,confirm:true}` 只落 `plugins-enabled.json`，响应固定 `executed:false`。

装配顺序（对应「硬编码层需要搭配启动运行的插件才显示」）：① 品牌署名先落地，永远显示，不等任何主题；② 读 `theme-active.json`，主题必须「目录存在 + 校验通过 + 已激活」三者同时满足才挂 `data-mcort-theme` 并注入 CSS；③ 槽位只在主题有效且 `requires` 全在内置模块表里时渲染，否则槽位为空；④ 玩法插件只影响它自己的条目，不影响品牌与主题。

## 8. 为什么先不执行插件 JS

`main.js` 一旦执行就等同于把任意代码放进工具箱进程：能读 `dataDir`（账号、设备令牌、日志）、能发本机 HTTP、能改前端 DOM——等于绕过本轮所有品牌守卫和权限。骨架阶段的正确做法是：服务端只做「发现 + 校验 + 记录启用」，前端只展示，执行层等三件事齐了再开：显式白名单（`yyThemePluginWhitelist`，当前为空）、用户二次确认（`confirm:true` 已强制）、以及独立进程/沙箱与能力声明（`capabilities`）。用户要的「跟我们接入种子查询器这种都差不多」最终应落在**受控能力调用**上，而不是直接 eval 第三方脚本。
