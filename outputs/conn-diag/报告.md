## 四、① 最长连续在线永远是 0 —— 根因

- `youyuan_connection_report.go:50` 定义 `yyDrops.best`。
- `youyuan_connection_report.go:149-153`：`best` **只在「掉线结算」这一个分支里更新**。
- `youyuan_connection_report.go:379 / :457`：读出来原样返回 `longest_uptime`。
- 前端 `youyuan_connection_diagnostics.js:71` 直接 `duration(d.longest_uptime)`。

所以：进程起来后一直在线、一次都没掉过线 → `best` 从未被赋值 → 恒为 `0` → 面板永远显示「0 秒」。而且 `best` 只在内存里，进程重启也清零。这符合用户说的「永远是零，这个是假的」。

**修法**（`youyuan_connection_report.go`，新增 `yyUptimeMerge` / `yyUptimePersistNow` / `yyUptimePath`）：
1. 读诊断时 `best = max(best, uptime)`，即「至少从本次连接建立时刻算起」；
2. `best` 落盘 `<dataDir>/connection-uptime.json`（`{"best_seconds":…, "updated_at":…}`），读取时取 `max(内存, 落盘, 本次)`；
3. 掉线结算时立即写盘（低频）；诊断轮询路径限流「创新高且距上次写盘 ≥1 分钟」才写，不会把磁盘打满；
4. 加锁顺序固定为 `yyDrops → yyUptimeState`，无反向持锁，不会死锁。

## 五、② 刷新导致界面右移漂移 —— 根因与修法

根因（两个文件叠加，都不在本 agent 文件里，我用本 agent 的 CSS 覆盖修）：
- `youyuan_connection_policy.js:110-130`：`#yy-server-refresh-label` 的文案每秒在
  「在线玩家 · 每 60 秒自动刷新」（18 字）和「在线玩家 · 每 60 秒自动刷新 · 59 秒后」（24 字）之间来回换。
- `youyuan_room_discovery.css:27-29`：`.yy-server-hero .yy-room-current-actions{flex-wrap:nowrap}`、
  `.yy-server-hero .yy-room-refresh span{white-space:nowrap}`，label 宽度 = 内容宽度。

于是整行固有宽度每秒抖一次 → 任何 `overflow-x` 祖先的水平滚动范围跟着抖 → 浏览器每秒 clamp / 重算滚动位置 → 容器自己在漂；用户按住拖动时抖动被放大，就变成「我往哪边移它往哪边移得更猛」，同时垂直可滚动高度也被重算，所以「拉不到底」。

修法（`youyuan_connection_diagnostics.css:45-64`，用 `#tab-settings #yy-connection-server-info` 前缀压过 room_discovery 的规则）：
- 刷新组定宽 `flex:0 0 216px`，label 定高 `16px` + 单行省略 + `tabular-nums`，range 定 `100%` → **文案怎么变，盒子尺寸都不变，零重排**；
- 操作行恢复 `flex-wrap:wrap`，`overflow-x:clip` 兜底；≤420px 时刷新组独占一行。

## 七、实时感知的显示策略（对应第 3 条）

- 进页面**一次拉全量铺满**（表 + 事件 60 条 + 抓包 12 条），不留白；
- 之后每 4s 只做增量：`<tr>` 按 `runtime_id` 复用，`yySenseCell` 只在 `textContent` 变化时写；实体消失要连续两轮缺席才删行，避免 `present_only` 抖动；
- 事件时间线用 `/api/youyuan/sense/events` 返回的 `cursor` 判等，没新事件不写 DOM；展示也从「整体 JSON.stringify」改成「时间 + 事件 + 详情」的可读行；
- 抓包列表按 `seq` 增量插入/剔除，`<details>` 展开状态和 `scrollTop` 不再被重建吃掉；
- 「暂停刷新 / 继续刷新」一键停轮询（后台抓包仍在记录）；`document.hidden` 时不拉接口；
- `diagnostics.visibility` 是慢接口，只在首次进入和手动刷新时拉，不跟 4s 轮询跑。

## 八、打开连接界面会刷新一次 / 覆盖原页面（第 5 条）

- 子页侧：`yySensePage()` 原来每次 `delete subPageCache["实时感知与抓包"]` 再 `openSubPage(整页骨架)`，进去必白一下再重填。现在只有 `subPageCache` 里没有时才建骨架，否则传空走缓存分支复用 DOM。
- 设置页侧：`Rcfg` 每次重建 `#tab-settings`（`youyuan_settings.js:28`），卡片必然是新节点。现在卡片创建后先 `draw(lastData)` 把上一份数据画回去（不出现「未读取」空窗），并按 `sessionStorage['yy-conn-diag-open']` 恢复展开状态。

## 九、④ 游戏内「等级显示乱码」方案对比（只出方案，没实现）

前提（已核实）：基岩版计分板只有 `list` / `sidebar` / `belowname` 三个显示槽，只有 `dummy` 标准，**没有 `/team`**，所以真实玩家 gamertag 上加不了 `§`；`belowname` 槽显示的是纯数字，无法打码。能打码的只有「条目名 / 显示名 / title 文本」里我们自己写的字符串。

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A. 伪条目 + §k 打码（推荐）** | 给计分板加一条**假玩家**条目，条目名写成 `§kLv84§r`（定长，如 8 个 §k 字符），分数固定 0；`sidebar` 里别人看到的是等宽乱码块，看不到数值 | 只靠原版命令，不需要改客户端；数值彻底不可读；真值存在另一个 objective 里，机器人自己照样用 | 命令参数里含 `§` 必须用引号包起来；假玩家名里的 `§` 在部分版本/客户端可能被过滤，需实机验一次；**乱码块宽度固定，能数出字符数**，所以必须定长 |
| **B. 隐藏（最稳）** | 把 `list` / `sidebar` 槽让给别的 objective，机器人的等级 objective 不设 display；或分数恒设 0 且不写等级 | 零风险、零维护，一行命令 | 别人是「看不到」而不是「看到乱码」，不满足「显示乱码」的字面诉求 |
| **C. 数值抖动** | 每 5s 把展示用 objective 的分数在真实等级 ±20% 内随机 | 看起来像真数据，无法确定具体值 | 要常驻定时器刷命令（有开销）；量级仍暴露；观感假，容易被看出在跳 |
| （不可行）| `/titleraw @a actionbar` 打码 | 能显示任意 `§k` 文本 | actionbar 会被每个人的其他提示顶掉，且每秒刷屏；影响所有玩家，不适合常驻 |
| （不可行）| 用 `/xp` 改真实等级 | 无需额外机制 | XP 等级只能显示数字，没有任何打码手段 |

建议：先用 **A** 做定长伪条目（视觉上就是「乱码等级」），若实机发现 `§` 被过滤就退到 **B**。
