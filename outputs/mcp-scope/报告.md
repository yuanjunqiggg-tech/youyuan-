**谁能调 / 权限判断只看 admin 吗**：不是只看 admin，是三道闸，且**全部与「哪台服务器、哪个人」无关**：

1. `youyuan_qq_ai.go:99` `if admin {` —— 三个 MCP 工具的定义只放进管理员工具集；普通群友的 schema 里根本没有这三个工具名。

3. `youyuan_qq_ai.go:453` `yyQQRunAIToolEx` 开头 `yyQQAIToolAllowed` 再查一次，模型硬调也拒。

执行侧完全没有身份概念：`youyuan_qq_ai.go:575-610` 三个 case 都写死 `yyWorkspaceMCP(ctx, ws, "group", ...)`；`youyuan_agent.go:946` `yyWorkspaceMCP` 只按 id 在 `ws.Servers` 里找、只看 `Enabled`。**结论：现状是一台「广泛性」的公用 MCP，但只给管理员；「绑某个人自己机器」这件事在代码里根本不存在。**

## 二、新字段表（`youyuan_mcp_scope.go:49`，落盘 `<dataDir>/mcp-servers.json`，0600）

| 字段 | 取值 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | 1–64 字母数字 `-_.` | 是 | 服务器标识，AI 用它在 `mcp_list(server=…)` 里指名 |
| `name` | 文本 | 否 | 显示名，空则取 id |
| `scope` | `public` / `private` | 是（缺省 public） | public=配在这台机器上、按 access 给群友用；private=绑某个群友自己的机器 |
| `owner` | 群友 QQ 号 | private 必填 | scope=private 时的归属人；`access=owner_only` 时也必填 |
| `access` | `all` / `admin` / `owner_only` | 是（缺省 all） | public 时生效；private 会被强制改写为 `owner_only`（`:104`） |
| `transport` | `stdio` / `http` / `sse` | 是（缺省按有无 command 推断） | http=公网直连/官方通道；sse=内网穿透常见；stdio=本机进程 |
| `url` | http(s) 地址 | http/sse 必填 | `:137` 校验 scheme 与 host |
| `command` + `args` | 可执行文件 + 参数数组 | stdio 必填 | 例 `npx -y @modelcontextprotocol/server-filesystem` |
| `headers` | 键值表 | 否 | 密钥放这里，如 `Authorization: Bearer xxx` |
| `note` | 文本 | 否 | 备注「家里 Cloudflare 隧道」之类，不参与判定 |
| `enabled` | 布尔 | 是 | 停用后一律拒（`yyMCPScopeGuard` 第一道） |

落盘原子写（`tmp` + `Rename`，`:165`）；`headers` 读接口只回 `header_keys`，**不回值**（`:313`）。

## 三、权限矩阵

判定唯一入口 `yyMCPScopeGuard(id, actor, level)`（`:252`）。`actor` = 群友 QQ 号或 `yyMCPActorLocal`（网页控制台的操作员）；`level` = 0 普通群友 / ≥1 管理员。

| scope | access | 普通群友 | 管理员 | 归属人 | 本机操作员 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| public | all | ✅ | ✅ | ✅ | ✅ | 真正的「全群可用」 |
| public | admin | ❌ | ✅ | ❌ | ✅ | 默认值以外的显式收缩 |
| public | owner_only | ❌ | ❌ | ✅ | ✅ | 公共机器上的私人工具 |
| private | （强制 owner_only） | ❌ | ❌ | ✅ | ✅ | 「A 调不到 B 的机器」由这一行保证 |
| 未登记（老 id，如 `group`） | — | ❌ | ✅ | — | ✅ | 沿用历史行为，见 `:619` 的 `yyQQMCPScopeGuard` |

配套的两处「可见性」逻辑：`yyMCPConnVisible`（`:291`，列出该身份真能调的服务器，供 `mcp_list` 用）、`yyMCPConnOpenToAll`（`:303`，是否存在 public+all 的服务器，决定要不要给群友下发工具名）。

## 四、连通性测试的实现

`yyMCPConnTest`（`:527`）+ 路由 `op=test`（`:643`）。点按钮 → `POST /api/youyuan/mcp/scope {op:'test'}` → 后端**真的连一次**：

1. `yyMCPConnNormalize` 先校验字段（地址/命令缺哪个直接在这里报，不会去打网络）。
2. 按 `transport` 分派：`http`/`sse` 走 `yyMCPHTTPRPC`（`:372`，带 `headers`、`MCP-Protocol-Version`、可选 `Mcp-Session-Id`，兼容 JSON 与 `text/event-stream` 两种响应）；`stdio` 走 `yyMCPStdioRPC`（`:449`，起进程 → 写 JSON-RPC 行 → 读回匹配 id 的行）。
3. 依次执行 `initialize` →（HTTP）`notifications/initialized` → `tools/list`，30 秒超时。
4. 回显：`ok`、`transport`、`target`（真实地址或命令）、`protocol`（协商版本）、`server`/`server_version`、`tool_count`、前 20 个工具名、`elapsed_ms`、失败时的 `error`。握手成功但目录取不到时返回 `ok:true, partial:true, tools_error` —— 说明「地址和鉴权对了，只是没工具」，便于区分是配错地址还是对端没工具。
5. **先测再存**：表单带了 `url`/`command` 就测表单当前值；只传 `id` 才测已保存那条；测表单时若没填 `headers`，自动带上已保存的（面板不回显密钥，否则会被 401 误导）。
