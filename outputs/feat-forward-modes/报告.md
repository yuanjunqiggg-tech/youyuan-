## ② 四模式配置结构

结构体：`youyuan_qq_assistant.go:44-56`（仍写进 `qq-bridge.json` 的 `assistant` 段，不新开配置文件）

```jsonc
"assistant": {
  "relay_mode": "off",              // off | keyword | auto | interval，默认 off
  "relay_keywords": "进服\n开服了吗,什么时候开",  // 换行/逗号/顿号/分号都可分隔，keyword 模式命中任一即转
  "relay_interval_minutes": 10,     // 定时打包间隔，夹 1..1440，0 = 默认 10
  "relay_max_messages": 20,         // 单次打包条数，夹 1..200，0 = 默认 20
  "relay_chat": false               // 旧布尔，仅为读旧配置保留；新模式保存后置 false
}
```

- 归一化：`yyQQRelayMode()`（`youyuan_qq_relay.go:78`）—— 空值/拼错一律 off；**只有 `relay_chat=true` 且没写 `relay_mode` 的旧配置按 auto 处理**，老用户升级后行为不变。
- 触发词拆分：`yyQQRelayKeywords()`（`:96`）—— 换行、`,`、`，`、`、`、`;`、`；`、`|` 都是分隔符，去空白去空项，匹配不区分大小写。
- 新旧开关冲突：`yyQQRelaySave()`（`:484`）保存新模式时把 `relay_chat` 置 false（新模式接管）；`yyQQRelayLegacyWillSend()`（`:149`）在 auto 模式下若旧分支仍会发同一行，就**跳过自己这一次**，绝不重复刷屏。
- 采集点：`youyuan_qq_context.go:158` 在 `yyQQRememberGroupMessageMeta` 末尾接 `yyQQRelayOnMessage(cf, msg)`。位置在群规硬拦、幂等门（`yyQQClaimMessage`）之后，所以违禁词与被适配器重推的消息都不会被转发；`isBot`、`/`、`.` 开头的消息直接跳过。

接口：`GET/POST /api/qq/relay`（`yyQQRelayRoutes`，`youyuan_qq_relay.go:631`）
- GET 返回 `mode / mode_label / keywords / interval_minutes / max_messages / queued / queued_by_group / last_at / last_count / sent_total / legacy_relay_chat / hint`
- POST 接受 `{mode, keywords, interval_minutes, max_messages, clear_queue}`，校验+夹取后写 `qq-bridge.json`，**不改连接参数 → 不触发断线重连**
- 三查已接：`youyuan_catalog.go:180`（`api_qq_relay`）、`youyuan_mcp_links.go:41`（只读表，POST 仍要管理连接）、`mux.HandleFunc` 在 `yyQQRelayRoutes` 内，函数由 `youyuan_remote.go:166` 调起

## ③ interval 模式的打包规则

`yyQQRelayEnqueue/Take/BatchText/Flush`（`youyuan_qq_relay.go:246/267/329/348`），轮询 15 秒一次（`:392`）：

1. **入队**：只收 interval 模式下、非指令、非机器人自己发的消息；按 `message_id` 去重（`Seen` 表 30 分钟过期）。
2. **计时起点**：某群第一条消息进队列时才立 `Last[group]=now`，保存配置时也重置 —— 打开开关不会把历史积压一股脑发出去。
3. **到点**：`now - Last[group] >= interval_minutes` 才打包；`off/keyword/auto` 时队列清空（切走模式不留残渣）。
4. **取批**：按 `At` 升序排 **稳定排序**，取最旧的最多 `max_messages` 条，**剩下的留在队列下一轮继续**，不丢。
5. **正文**（`yyQQRelayBatchText`）：
   ```
   〔互通群 · 7 条群聊〕
   张三：晚上开吗
   李四：开了
   …另有 3 条，下一轮继续
   ```
   每行「昵称：内容」（昵称取 `yyQQDisplayName` 后的显示名），单行超 200 字截断，换行压成空格（一行一条，不炸屏）。
6. **失败重试**：游戏没连上时整批塞回队列头部，保留 `Tries`，连续 3 轮发不出去才丢（日志只记一次，避免每 15 秒刷一条）。
7. **容量**：总队列上限 500 条，超了丢最旧的并在下次打包尾部注明「队列已满，丢弃了 N 条」。

## ④ `.通` 的新指令

`yyQQRelayGameCommand()`（`youyuan_qq_relay.go:586`），在 `yyQQGameSelection` 最前面接线（`youyuan_qq_selection.go:138`），**复用现有 `relay` 别名（默认 `.通`，玩家可在指令别名表里改）**，没有新造指令 ID：

| 指令 | 作用 |
|---|---|
| `.通 内容` | 手动转，老行为不变（命中不了 `状态/自动` 就落回原路径） |
| `.通 状态` | 回执：当前模式、间隔与上限、排队条数、触发词（keyword 模式）、上次转发时间与条数、怎么切 |
| `.通 自动 开` | 切 auto（每条都转）并立即落盘 |
| `.通 自动 关` | 切 off 并立即落盘 |
| `.通 自动` | 只回格式提示 |

- 只有 **整词** `状态` / `自动` 才拦截，`.通 自动贩卖机真方便` 这种照旧当消息发出去。
- 回执走 `yyQQGameNotice`（tellraw 给本人），不占群消息。
- 与老 `.通` 一致的已知边界：整套 `.通` 只在 `Assistant.Enabled` 时可用（`youyuan_qq.go:747`），关闭助手时 `.通 状态` 同样不响应。
